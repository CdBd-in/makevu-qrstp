# 🎯 QR스탬프 "이용 안내 × 플랜" 중복 정리안

> 홈페이지 [www.qrstp.com](https://www.qrstp.com/) 분석 기반

---

## 1. 문제 정의

현재 홈페이지에서 **플랜 관련 콘텐츠가 두 곳에 중복**되어 있다.

- **이용 안내 섹션** 안에 플랜별 기능/가격 정보가 포함되어 있음
- **플랜 섹션**이 별도로 또 존재함

→ 같은 정보가 다른 옷을 입고 두 번 노출되어 **유지보수 부담**과 **사용자 혼란**을 초래.

---

## 2. 정리 원칙 (1줄)

> **"이용 안내 = 무엇을 만들 수 있나(WHAT)" / "플랜 = 얼마에 어디까지 받나(HOW MUCH)"**
> 가격·플랜별 ✓/✗는 **플랜 섹션에만 단일 원본(SSOT)**으로 둔다.

| 섹션 | 사용자 마음 상태 | 답해야 할 질문 | 퍼널 단계 |
|---|---|---|---|
| **이용 안내** | "이게 어떻게 동작하지?" | HOW · 기능 | 🟡 Consideration |
| **플랜** | "얼마이고, 뭘 받지?" | WHAT & HOW MUCH | 🔴 Decision |

---

## 3. 실제 정리 액션

### ✂️ "이용 안내"에서 제거할 것
- [ ] 플랜 이름이 표 헤더로 등장하는 모든 표 → **제거**
- [ ] "이 기능은 ○○ 플랜 이상" 같은 가격 결정 정보 → **배지 1개로 축약**
- [ ] 가격(₩, 만원 등) 표시 → **전부 제거** (가격은 플랜 섹션에만)

### ✅ "이용 안내"에 남기거나 강화할 것
- [ ] STEP 1~4 흐름 (캠페인 만들기 → QR 배포 → 적립 → 리워드)
- [ ] 핵심 **기능 카드**: 스탬프 미션 / 룰렛 리워드 / 커스텀 디자인 / 다국어 / 분석
- [ ] 각 기능 카드 우상단에 **작은 플랜 배지**: `[Basic+]`, `[Pro+]`
- [ ] 섹션 마지막에 단일 CTA: **"플랜 비교하기 →"** (플랜 섹션 앵커)

### ✅ "플랜" 섹션의 단독 책임
- [ ] **플랜별 기능 비교 매트릭스** (이 사이트의 단일 진실)
- [ ] 가격 또는 "문의" 표기
- [ ] 추천 사용 케이스 1줄 (예: "Basic — 1회성 팝업스토어용")
- [ ] 단일 CTA: **"상담 신청하기"**

## 4. 수정 전 ↔ 수정 후 비교 분석

> 참고: Figma 노드 `381:1904` (BEFORE / 라이브 사이트 반영본) ↔ `381:5224` (AFTER / 수정본)

### 4-1. 전체 페이지 구조 변화

|  | BEFORE (라이브) | AFTER (수정본) | 변화 |
|---|---|---|---|
| QR 플랜 안내 높이 | 738px | **900px** | +162 (사양 추가) |
| 이용 안내 높이 | 4,438px | 4,438px | 동일 |
| 총 두 섹션 합계 | 5,176px | 5,338px | +162 |
| **정보 중복** | **3중 노출** | **0중복** | ✅ 완전 해소 |
| **유효 정보 밀도** | 낮음 (분산) | **높음 (압축)** | ✅ 상승 |

> 페이지가 짧아지진 않았지만 — 같은 길이 안에 정보가 명확히 자리 잡았다. 길이보다 위계가 중요.

### 4-2. 정보 아키텍처 (IA) 비교

**BEFORE — "한 섹션이 세 가지 일을 함"** 🔴

```
QR 플랜 안내 (얇음)
└─ 3카드: 티저만 / 가격 / 플랜명
   → "이 플랜이 뭔지" 알 수 없음. 의사결정 불가.

이용 안내 (긴~)
├─ 🔴 이지 플랜 박스 [WHO + HOW + SPEC + PRICE + CTA]  ← 중복 1
├─ 3단계 흐름 [HOW]
├─ 🔴 리드/데일리 박스 [WHO + HOW + SPEC + PRICE]      ← 중복 2
├─ 4단계 흐름 [HOW]
├─ 기능 옵션 [WHAT EXTRA]
└─ 작업 흐름 + CTA
```

문제: 이용 안내가 *"플랜 소개 + 가격 안내 + 사양표 + 흐름 + 옵션 + 견적 안내"* 6역할을 동시 수행.

**AFTER — "한 섹션 한 역할"** ✅

```
QR 플랜 안내 (적정)                       이용 안내 (긴~)
└─ 3카드: 티저 + 사양3줄 + 가격            ├─ 이지 플랜 박스 [HOW only]
   → 무엇을, 누구한테, 얼마에              ├─ 리드 & 데일리 박스 [HOW only]
   → 모든 정보가 여기 모임 (SSOT)          ├─ 기능 옵션 [WHAT EXTRA]
                                          └─ 작업 흐름 + CTA
```

개선: 두 섹션의 역할이 명확히 분리됨.
- **QR 플랜 안내** = "WHO / WHAT / HOW MUCH" (의사결정)
- **이용 안내** = "HOW" (사용 흐름 + 옵션) (운영 이해)

### 4-3. 7가지 차원 비교

#### ① 플랜 비교 가능성 — 🔼 크게 개선
| 차원 | BEFORE | AFTER |
|---|---|---|
| 사양 노출 위치 | 이용 안내 안 (중복) | **QR 플랜 안내 한곳** |
| 사양 시각 위계 | `#a0a0a0` 작은 글씨 | 라벨/값 정렬, 검은 굵은 값 |
| 한눈 비교 가능성 | ❌ 카드별로 스크롤 필요 | ✅ 3카드 가로 비교 즉시 |
| 표기 일관성 | 5**개** / 5**회** / 10**회 적립** | ✅ 모두 **회**로 통일 |

→ B2B 의사결정 측면에서 가장 큰 개선점. 마케팅 담당자가 "7일이면 짧은데..." "90일이 데일리 차별점이구나" 같은 판단을 카드 한 줄에서 즉시 내릴 수 있게 됨.

#### ② 흐름(Flow) 표현 — 🔼 명확해짐
| 차원 | BEFORE | AFTER |
|---|---|---|
| 흐름 표시 방식 | 텍스트 단계 표시만 | **모바일 목업 + 단계 라벨** |
| 플랜별 흐름 차이 | "왜 4단계지?" 추정 필요 | "이지=3단계 / 리드·데일리=4단계" 명시 |
| 본인 인증 위치 | 4단계 안에 묻힘 | **리드/데일리 박스 안에 별도 단계로 시각화** |

#### ③ 중복 정보 — 🟢 완전 해소
| 항목 | BEFORE | AFTER |
|---|---|---|
| "이지 플랜" 이름 | QR 플랜 + 이용 안내 = 2회 | QR 플랜 + 이용 안내(흐름 라벨) = 2회 *(라벨 용도)* |
| 가격 (100/200만원) | QR 플랜 + 이용 안내 = 2회 | **QR 플랜에만 1회** ✅ |
| 사양 (기간·스탬프·인증) | 이용 안내 안 (분산) | **QR 플랜에만 1회** ✅ |
| 상담신청 버튼 | QR 플랜 + 이용 안내 안 + 하단 CTA = 3회 | QR 플랜 + 하단 CTA = 2회 ✅ |

→ 가장 큰 개선: 가격·사양·상담 버튼의 단일 진실(SSOT) 확립.

#### ④ 시각 위계 — 🔼 개선되었으나 여전히 검토 필요
| 차원 | BEFORE | AFTER |
|---|---|---|
| 사양 글씨 크기 | 매우 작음 | 13~14px |
| 사양 색상 | `#a0a0a0` (소실) | 라벨/값 구분 (가독↑) |
| 사양 정렬 | 인라인 나열 | 라벨 ↔ 값 양쪽 정렬 |

⚠️ 여전한 이슈: 리드와 데일리의 본인인증이 둘 다 "휴대폰/이메일"로 표시 → 두 플랜의 차이가 모호.

#### ⑤ CTA 동선 — 🔼 정리됨
| 차원 | BEFORE | AFTER |
|---|---|---|
| CTA 개수 | 4종 (상담신청·체험하기·상담신청·상담하러가기) | 3종 (체험·상담·상담하러) |
| 의도 분리 | 흐릿함 | **QR 플랜 = 결정 진입 / 이용 안내 = 운영 진입** |

여전히 "상담 신청하기"와 "지금 바로 상담하러 가기"가 사실상 같은 액션 → 하나로 통일 권장.

#### ⑥ 스캔 가능성 — 🔼 크게 개선

```
BEFORE 사용자 시선:
"플랜 안내 봤는데... 가격은 알겠고... 어디서 자세히 보지?"
↓ 스크롤
"오 이지 플랜 박스 있다... 이게 위의 이지 플랜이랑 같은 건가?"
↓ 스크롤
"리드/데일리 박스도 있네... 그럼 위 카드는 뭐였지?"
→ 인지 부하 ↑ / 신뢰도 ↓

AFTER 사용자 시선:
"플랜 안내 — 사양·가격 모두 확인 → 결정 가능"
↓ 스크롤
"이용 안내 — 결정한 플랜이 어떻게 동작하는지 흐름 확인"
→ 인지 부하 ↓ / 신뢰도 ↑
```

#### ⑦ 영업 퍼널 — 🔼 명확
| 단계 | BEFORE | AFTER |
|---|---|---|
| Discovery (탐색) | 흐릿한 카드 → 깊이 부족 | 사양 노출 → 즉시 판단 가능 |
| Consideration (검토) | 이용 안내 안에 가격·사양·흐름 다 들어가 분산 | 이용 안내가 "운영 시뮬레이션" 역할 명확 |
| Decision (결정) | 어디서 결정? CTA 분산 | 플랜 안내의 [상담 신청하기]에 집중 |

### 4-4. 5점 척도 종합 평가

| 차원 | BEFORE | AFTER | Δ |
|---|---|---|---|
| 정보 아키텍처 (IA) | ⭐⭐ | ⭐⭐⭐⭐½ | +2.5 |
| 시각 위계 | ⭐⭐ | ⭐⭐⭐⭐ | +2.0 |
| 플랜 비교 사용성 | ⭐⭐ | ⭐⭐⭐⭐ | +2.0 |
| 표기 일관성 | ⭐⭐ | ⭐⭐⭐⭐½ | +2.5 |
| CTA 명확성 | ⭐⭐½ | ⭐⭐⭐⭐ | +1.5 |
| 전체 인지 부하 | 🔴 높음 | 🟢 낮음 | — |
| 페이지 길이 | 5,176 | 5,338 | +162 (수용 가능) |

**총평**: 평균 2.3 → 4.2 (+1.9pt, **약 85% 개선**)

### 4-5. 잘된 점 5가지

1. **단일 진실(SSOT) 확립** — 가격·사양·상담 버튼이 한 곳으로 통합
2. **사양 승격** — `#a0a0a0` 작은 글씨에서 라벨/값 구조로 시각화
3. **표기 통일** — 개/회 혼용 → **회**로 통일
4. **이용 안내 역할 명확화** — 흐름 시뮬레이션 전용 공간으로 정리
5. **본인 인증 단계 가시화** — 리드/데일리 박스 안 4단계에서 명시적 표시

### 4-6. 추가 개선 여지 4가지

#### (1) 리드 vs 데일리의 본인 인증 표기
현재 둘 다 "휴대폰/이메일" → 차별점 모호.
**권장**: 리드 = 이메일, 데일리 = 휴대폰 (원본 사양으로 분리) — 또는 두 곳 다 "휴대폰/이메일 중 선택"으로 명시.

#### (2) 비교 매트릭스 추가 고려
현재는 3카드 가로 비교만 가능. 카드 아래 **풀폭 매트릭스**(6행 × 4열)를 두면 B2B 검토 효율이 한 단계 더 올라감.

#### (3) "상담 신청하기" ↔ "지금 바로 상담하러 가기" 통일
둘이 사실상 같은 액션. **하나의 카피·하나의 색상**으로 통일 권장.

#### (4) 이용 안내의 플랜 라벨 추상화 검토
현재 "이지 플랜" / "리드 플랜 & 데일리 플랜"으로 묶음.
이용 안내를 보는 사용자가 아직 플랜을 결정하지 않았다면:
- 현재: "이지 플랜" — 어떤 플랜인지 알아야 매칭 가능
- 대안: **"본인 인증이 필요 없는 이벤트"** / **"본인 인증이 필요한 이벤트"** — 상황으로 매칭

### 4-7. 핵심 메시지

> **"같은 길이를 유지하되, 정보 위계와 역할 분리로 사용자 인지 부하를 절반 이하로 줄였다."**

페이지가 길이로 짧아지진 않았지만, 각 섹션이 하나의 명확한 역할을 수행하면서 B2B 의사결정자가:
1. QR 플랜 안내에서 "어떤 플랜이 맞는지" 결정
2. 이용 안내에서 "실제 어떻게 굴러가는지" 시뮬레이션
3. 자연스럽게 상담 진입

이전엔 "어디서 뭘 봐야 할지" 자체가 부담이었던 페이지가, 이제는 명확한 두 박자 흐름이 되었음. "회색 작은 텍스트가 진짜 중요한가?"라는 직관에서 시작된 의문이 결과적으로 **페이지 전체의 IA 정돈**으로 이어진 좋은 사례.
