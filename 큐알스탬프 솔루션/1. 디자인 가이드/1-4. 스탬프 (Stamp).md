# 🏷️ 1-4. 스탬프 (Stamp)

> 4단계 중 **3단계**. QR 스캔 포인트마다 스탬프를 적립하고 진행 상황을 확인.
> 관련: [[큐알스탬프 솔루션/0. 정의 및 과정.md]] · [[큐알스탬프 솔루션/1. 디자인 가이드/1-1. 공통 디자인 시스템.md]]

---

## 1. 정의

각 QR 스캔 포인트에서 **스탬프가 적립**되며, 참여자는 **적립 현황(진행률)**을 실시간으로 확인한다.
게임처럼 직관적으로 설계되어 완주의 재미를 제공하고, 조건 충족 시 리워드 신청으로 이어진다.

---

## 2. 두 가지 모드

### A. Single Reward (단일 리워드)
하나의 리워드를 향해 스탬프를 모으는 기본형.

| 상태(frame) | 헤드라인 예시 | 버튼 |
|---|---|---|
| `Single_Disabled` | "홍길동님, 4개의 스탬프를 더 모으고 리워드를 받으세요" | 비활성 |
| `Single_Enabled` | "스탬프를 모두 모았어요! 리워드를 신청하세요" | **활성** [리워드 신청하기] |
| `Single_Done` | "축하드려요! 리워드 신청이 완료되었어요" | 비활성(완료) |

### B. Multiple Rewards (다중 리워드)
리워드 A/B/C 등 여러 단계 리워드를 **탭**으로 전환.

| 상태(frame) | 헤드라인 예시 | 버튼 |
|---|---|---|
| `Multi / A / Enabled`(미충족) | "1개의 스탬프를 더 모으고 리워드A를 받으세요" | 비활성 |
| `Multi / A / Enabled`(충족) | "스탬프를 충분히 모았어요! 리워드A를 받으세요" | **활성** |
| `Multi / A / Done` | "축하드려요! 리워드A 신청이 완료되었어요" | 비활성(완료) |

---

## 3. 무엇이 들어가는가 (구성 요소)

1. **개인화 헤드라인** — "{이름}님, …" + 남은 개수/완료 상태 (`Title_L`, 강조어 primary)
2. **CTA 버튼** — [리워드 신청하기] (상태별 활성/비활성)
3. **스탬프 그리드** — `Frame 21`, **2열** 배치 + 점선 구분선
   - **Stamp(Stamped)** — 적립된 도장(primary)
   - **Stamp(Empty)** — 미적립 고스트(번호 01~05)
   - **Stamp_Multi** — 다중 리워드의 리워드 경계 표시
4. **(다중 전용) 리워드 탭** — 리워드 A / B / C (`Tab`, 선택=primary)
5. **상태 설명 노트**(디자인 참고) — `Description / Single 1·2·3`, `Multi 1·2`
   - 조건 미충족 → 필요한 스탬프 개수 안내
   - 조건 충족 → 버튼 활성 + 텍스트 변경
   - 신청 완료 → 버튼 비활성 + 텍스트 변경

---

## 4. 사용 리소스 (디자인 시스템)

| 요소 | 토큰/컴포넌트 |
|---|---|
| 헤드라인 | `Title_L` · text `#212529` / 강조 primary `#4B73FF` |
| 스탬프 | **Stamp** 컴포넌트 (100×100, Stamped/Empty/Multi) |
| 그리드 구분선 | 점선(dashed), placeholder `#C0C0C0` |
| 리워드 탭 | **Tab** (Selected primary / Default gray) |
| CTA | **Button** (Disabled↔Enabled) |
| 레이아웃 | 375 × 812 · 여백 24 · 스탬프 2열 그리드 |

---

## 5. 디자인 시 체크포인트
- [ ] 남은 스탬프 개수 / 완료가 헤드라인에서 즉시 읽히는가
- [ ] 적립/미적립 스탬프가 시각적으로 명확히 구분되는가
- [ ] 단일/다중 모드가 동일 레이아웃 골격을 공유하는가
- [ ] 다중 모드에서 탭 전환 시 현재 리워드 진행상태가 분명한가
- [ ] 조건 충족 순간 CTA 활성 + 카피 변화가 자연스러운가
