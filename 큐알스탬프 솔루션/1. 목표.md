# 🎯 1. 목표

> 큐알스탬프 페이지를 만드는 **디자인 시스템 자동화**의 목표를 정의하는 문서

---

## 목적

**문서와 리소스를 던져주면, 과정별로 클로드(Claude)가 바로 디자인할 수 있게 한다.**

즉, 사람이 매번 처음부터 설명하지 않아도, 잘 정리된 **가이드 문서 + 디자인 리소스**만 입력하면 클로드가 큐알스탬프 페이지의 각 단계 화면을 즉시 설계·산출하도록 만드는 것이 목적이다.

---

## 목표

큐알스탬프 이벤트의 **4단계 과정**(→ [[큐알스탬프 솔루션/0. 정의.md]])마다, 클로드가 별도 설명 없이 바로 디자인을 시작할 수 있는 상태를 만든다.

```
1. 시작  →  2. 본인 인증  →  3. 스탬프 적립  →  4. 리워드 신청
```

각 과정별로 클로드가 즉시 디자인하려면 다음이 갖춰져야 한다.

| 구성           | 내용                                   |
| ------------ | ------------------------------------ |
| **문서 (가이드)** | 각 단계의 목적·화면 구성·플로우·요구사항을 정의한 설계 지침   |
| **리소스**      | 디자인 시스템(컬러·타이포·컴포넌트), 브랜드 에셋, 레퍼런스 등 |
| **출력 기준**    | **클로드가 Figma에 직접 디자인을 산출한다** (아래 참고) |

> 핵심: "문서 + 리소스 → 입력" 만으로 "과정별 디자인 → 출력"이 나오는 **반복 가능한 자동화 파이프라인**을 구축한다.

### 출력 기준 — Figma 직접 디자인

> **최종 목표는 클로드가 화면 명세나 코드가 아니라, Figma에 직접 디자인을 그려내는 것이다.**

- **산출물**: Figma 파일 내 **실제 프레임/화면 + 컴포넌트** (375×812 모바일 기준)
- **방식**: Figma MCP를 통해 클로드가 디자인을 생성·편집 (code/명세 중간 산출물이 아닌 **디자인 결과물 그 자체**)
- **기준 소스**: 기존 Figma "QR 스탬프" 파일의 디자인 시스템(변수·컴포넌트)을 그대로 재사용해 일관성 유지
- **입력 → 출력 흐름**:
  ```
  [문서 가이드 + 디자인 시스템/리소스]  →  클로드  →  [Figma 화면·컴포넌트]
  ```
- 따라서 `2. 디자인 가이드`의 모든 문서는 **클로드가 Figma에서 바로 그릴 수 있을 만큼** 토큰·사이즈·상태가 구체적으로 명시되어야 한다.

---

## 범위

- **포함**: 4단계 과정별 화면 디자인에 필요한 가이드 문서 및 리소스 체계 정리
- **제외**: *(추후 정의 — 예: 백엔드 로직, 실제 운영 배포 등)*
