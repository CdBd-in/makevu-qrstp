# 🧩 2-6. Figma 리소스 체계

> **클로드가 Figma에 직접 디자인할 때 재사용할 리소스의 단일 인덱스(SSOT).**
> 새 화면을 0부터 그리지 않고, **여기에 등록된 변수·컴포넌트·에셋만 조립**해 산출한다.
> 관련: [[큐알스탬프 솔루션/1. 목표.md]] · [[큐알스탬프 솔루션/2. 디자인 가이드/2-1. 공통 디자인 시스템.md]]

---

## 1. 원칙 (가장 중요)

1. **변수·컴포넌트는 새로 만들지 않는다.** 아래 인덱스에 있는 것만 참조·인스턴스화한다.
2. 색/폰트 값을 **하드코딩 금지** → 반드시 **Figma 변수명**으로 적용.
3. 새 화면 = **기존 컴포넌트 인스턴스 배치 + 변수 적용 + 콘텐츠 교체**.
4. 인덱스에 없는 요소가 필요하면 → **임의 생성 대신, 먼저 이 문서에 "신규 리소스 제안"으로 기록**하고 합의 후 추가.

## 6. 클로드 작업 규약 (How Claude uses this)

**입력 → 출력 흐름**
```
[가이드 문서(2-2~2-5) + 본 인덱스(2-6)]  →  클로드(Figma MCP)  →  [Figma 화면·컴포넌트]
```

**산출 절차**
1. 만들 단계의 가이드 문서(2-2~2-5)에서 **화면·상태·콘텐츠** 확인.
2. 본 인덱스에서 **기준 참조 프레임**(2절)을 복제하거나, **필요한 컴포넌트**(4절)를 인스턴스로 배치.
3. **변수**(3절)로 색·타이포 적용 (하드코딩 금지).
4. 콘텐츠(텍스트·이미지)만 단계별 가이드대로 교체.
5. 상태(variant)와 분기(예: 본인인증 유무, 단일/다중)를 가이드대로 반영.

**MCP 참고 흐름**
- `get_variable_defs` → 변수 확인 / `get_metadata` → 구조·컴포넌트 위치 / `get_design_context` → 구현 컨텍스트 / `get_screenshot` → 시각 확인
- 산출은 기존 컴포넌트 **재사용**을 우선한다.

## 7. 리소스 배치 규약 (디자인 가이드 내)

```
2. 디자인 가이드/
├── 2-1. 공통 디자인 시스템     # 토큰·컴포넌트 "정의"(사람이 읽는 규격)
├── 2-2 ~ 2-5 (단계별 가이드)   # 각 단계 화면 "요구사항"
└── 2-6. Figma 리소스 체계       # 토큰·컴포넌트·에셋 "인덱스"(클로드가 참조하는 레지스트리) ← 본 문서
```

- **2-1 = 정의(왜/무엇)**, **2-6 = 인덱스(어디서/어떻게 참조)** 로 역할 분리.
- 단계 문서(2-2~2-5)는 콘텐츠·상태에 집중하고, 공통 리소스는 **2-6을 단일 출처로 참조**.
