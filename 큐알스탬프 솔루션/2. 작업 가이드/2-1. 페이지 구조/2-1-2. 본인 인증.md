# 🔐 2-1-2. 본인 인증

> 4단계 중 **2단계**. 참여자 식별 및 리워드 지급 신뢰성 확보.
> 관련: [[큐알스탬프 솔루션/0. 정의.md]] · [[큐알스탬프 솔루션/2. 작업 가이드/2-2. 디자인 요소/2-2-1. 공통 디자인 시스템.md]]

> [!important] 이 단계는 **선택(옵션) 단계**입니다.
> 본인 인증은 **모든 QR 이벤트에 필수가 아니며**, QR스탬프 이벤트 **담당자의 요청에 따라 포함될 수도, 생략될 수도** 있습니다.
> - **포함 시**: `시작 → 본인 인증 → 스탬프 → 리워드` (4단계)
> - **생략 시**: `시작 → 스탬프 → 리워드` (3단계) — 시작 후 바로 적립현황으로 진입
> 따라서 이 화면은 **이벤트별로 켜고 끌 수 있는 모듈**로 설계한다.

> [!tip] 이벤트 적용 방법 — **이 페이지를 그대로 사용**
> 본인 인증을 사용하는 이벤트는 아래 두 프레임을 **그대로 가져와 사용**한다 (레이아웃·필드·동의·텍스트 모두 공통 고정).
> - `2-1. LOGIN-Default` — 전체 미입력 (초기 진입)
> - `2-2. LOGIN-Filled` — 전체 입력 완료
>
> **이벤트별로 바꾸는 것은 단 두 가지 버튼 컬러뿐:**
> - **[인증번호 받기]** 버튼 → **이벤트 메인 컬러**
> - **[시작하기]** CTA 버튼 → **이벤트 메인 컬러**
>
> 그 외 모든 요소(헤드라인·입력 필드·동의 체크박스·링크·팝업)는 **공통 디자인 시스템 그대로** 두고 색을 바꾸지 않는다.

---

## 1. 정의

**휴대폰번호 인증 한 번**으로 본인을 확인하는 단계.
중복·부정 적립을 방지하고 리워드 지급 대상을 정확히 식별한다.
헤드라인: **"휴대폰번호 인증 한 번으로 이벤트에 참여하세요"**

> ⚠️ **단, 이 단계의 존재 여부 자체가 이벤트 담당자 요청에 따라 결정된다.** (위 박스 참고)

## 2. 화면/상태 목록

| 상태(frame) | 설명 |
|---|---|
| `LOGIN / Default` | 초기 진입 (전체 미입력) |
| `LOGIN / Phone_Button_Enabled` | 휴대폰번호 입력 → [인증번호 받기] 활성 |
| `LOGIN / Veri_Sent` | 인증번호 발송됨 (05:00 카운트다운, [재전송]) |
| `LOGIN / Veri_Filled` | 인증번호 입력 완료 |
| `LOGIN_Button_Enabled` | 모든 조건 충족 → [시작하기] 활성 |
| `LOGIN_Error_empty` | 미입력 상태에서 제출 → 각 필드 Error |

---

## 3. 구성 요소

1. **헤드라인** (`Title_L`)
2. **입력 필드 3종**
   - 이름 — `Field_Name`
   - 휴대폰번호 — `Field_Phone` + 인라인 **[인증번호 받기]** 버튼
   - 인증번호 — `Field_Verification`
3. **링크** — "인증번호 문자가 오지 않을 때" (`link_ul`) → `NOMESSEGE_Popup`
4. **동의 체크박스 2종 (필수)**
   - 개인정보 수집 이용 동의 (필수) + "자세히" → `AGREE_Popup1`
   - 개인정보 처리업무 위탁 동의 (필수) + "자세히" → `AGREE_Popup2`
5. **CTA 버튼** — "시작하기" (`Button`, 하단 고정)

### 연결 팝업 (Modal)
| 팝업 | 내용 |
|---|---|
| `AGREE_Popup1` | 개인정보 **수집·이용** 동의 — 수집 항목(성명·휴대폰번호) / 목적(당첨자 확인·경품 배송·피드백) / 보유기간(배송 완료 후 14일 내 파기) |
| `AGREE_Popup2` | 개인정보 **처리업무 위탁** 동의 — 수탁업체((주)엠카) / 업무 내용(이벤트 진행) |
| `NOMESSEGE_Popup` | 인증 문자 미수신 안내 — 스팸 차단 / 통신사별 스팸함 / 착신전환 / 번호이동 |

## 4. 인터랙션 규칙

- **[인증번호 받기] 클릭** → 필드 포커스아웃, 버튼명 **[재전송]**으로 변경, 코드 유효시간 **05:00 카운트다운** 시작.
- **미입력 상태에서 [시작하기] 클릭** → 미입력된 각 필드에 **Error 피드백** 노출.
- 모든 필수 필드 + 필수 동의 충족 시에만 **[시작하기] 활성**.

> **⭐ 보조 버튼(인증번호 받기/재전송) 화면별 상태 (필수)**
> - `2-1. LOGIN-Default` = **[인증번호 받기]** (휴대폰번호 입력 전 = **비활성**, 입력 후 = 활성)
> - `2-2. LOGIN-Filled` = 인증 발송 후이므로 같은 버튼이 **[재전송]** 으로 바뀐 상태
> - **비활성 상태 = 활성(메인 컬러) 버튼 전체의 opacity 30%** — 주 CTA '시작하기'와 **동일 규칙**. (→ [[큐알스탬프 솔루션/2. 작업 가이드/2-2. 디자인 요소/2-2-1. 공통 디자인 시스템.md]] §4)

## 6. 인증 디자인 유형 (밑줄형 / 박스 인풋형) ⭐

> 인증 화면의 **폼 구성요소(이름·휴대폰·인증번호·동의)는 DS 고정**이다. 디자인은 **입력 필드 스타일 기준 2가지**로 나뉜다. (배경 명암 라이트/다크·메인 컬러는 두 유형 위에 얹는 **테마 축**으로 별개)

| 유형 | 입력 필드 | 특징 | 대표 이벤트 |
|---|---|---|---|
| **A. 밑줄형 (Underline)** ⭐기본 | 라벨 + **하단 밑줄**(언더라인) 필드 | DS 표준. 라이트/다크 배경 모두 동일 필드 스타일, 메인 컬러만 교체 | 민주평통 · 넷마블 · 세부에어 · TGG · 창대십리길 · WORLD PASSPORT |
| **B. 박스 인풋형 (Boxed)** | **외곽선/채움 박스**(라운드 사각) 필드 | 커스텀 스킨. 필드가 상자로 구분돼 밀도 높은 폼(성별 드롭다운·생년월일 분할 등)에 적합 | 티쏘 |

![[큐알스탬프 솔루션/attachments/auth-type-underline.png]]
> ▲ **A. 밑줄형** — 라이트(넷마블) / 다크 반전(WORLD PASSPORT). 필드는 라벨+밑줄, 배경 명암만 다름.

![[큐알스탬프 솔루션/attachments/auth-type-box.png]]
> ▲ **B. 박스 인풋형** — 티쏘. 각 필드가 외곽선 박스로 구분(다크+레드 커스텀).

- **선택 기준**: 기본은 **A(밑줄형)** — DS 그대로 재사용(위 [!tip]). 폼 필드가 많거나(성별·생년월일 등) 브랜드가 상자형 UI를 요구할 때만 **B(박스형)**.
- **명암(라이트/다크)** 은 유형과 무관한 별도 축 — A·B 모두 밝은 배경(다크 텍스트) / 어두운 배경(화이트 텍스트)로 테마링 가능. 밝은 메인 컬러 위 텍스트는 다크 처리.
- 이메일 추가·인증방법 선택·닉네임·언어선택 등은 **디자인이 아니라 폼 구성(기능) 옵션** → 두 유형 위에 얹는 가변 슬롯.

---

## 7. 디자인 시 체크포인트
- [ ] 필드 스타일이 유형 A(밑줄) / B(박스) 중 하나로 **일관**되게 적용됐는가
- [ ] `LOGIN-Default` = [인증번호 받기] / `LOGIN-Filled` = [재전송] 으로 버튼이 바뀌었는가
- [ ] 보조 버튼·CTA의 **비활성 = 활성 버튼 opacity 30%** 인가
- [ ] 인증번호 발송 후 카운트다운/재전송 상태가 명확한가
- [ ] 미입력 제출 시 어떤 필드가 문제인지 즉시 보이는가
- [ ] 필수 동의 2건이 시각적으로 구분되고 "자세히" 진입이 쉬운가
- [ ] 문자 미수신 안내 진입 경로가 노출되는가
