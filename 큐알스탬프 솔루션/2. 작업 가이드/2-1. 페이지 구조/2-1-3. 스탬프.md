# 🏷️ 2-1-3. 스탬프

> 4단계 중 **3단계** *(본인인증 생략 시 −1단계 → 2단계)*. QR 스캔 포인트마다 스탬프를 적립하고 진행 상황을 확인.
> 관련: [[큐알스탬프 솔루션/0. 정의.md]] · [[큐알스탬프 솔루션/2. 작업 가이드/2-2. 디자인 요소/2-2-1. 공통 디자인 시스템.md]]

---

## 1. 정의

각 QR 스캔 포인트에서 **스탬프가 적립**되며, 참여자는 **적립 현황**을 실시간으로 확인한다.
조건(전체 적립) 충족 시 리워드 신청으로 이어진다.

---

## 2. 표준 구조 (공통)

> 모든 스탬프 화면 공통 = **헤더 → 리워드 버튼 → 스탬프 그리드**. 상태에 따라 **헤더 문구 · 버튼 · 적립 개수**만 달라진다. (`n` = 전체 스탬프 수)

### 2-1. 세로 배치 & 간격
```
상단
 │ 52          ← 헤더 top
헤더 (개인화 + 상태 메시지)
 │ 29
리워드 버튼
 │ 29
스탬프 그리드
 │ 52
하단
```

> 🧩 **오토레이아웃**: 헤더·버튼·그리드는 **327폭 세로 오토레이아웃 컨테이너(높이 hug · gap 29)** 에 담긴다. 헤더 문구 줄 수나 스탬프 칸 수가 바뀌어도 **gap 29가 유지**되며 컨테이너 높이가 자동으로 늘어난다. (간격을 좌표로 고정 ❌)

### 2-2. 영역별 사양

| 영역 | 사양 | 폰트/컬러 |
|---|---|---|
| **헤더** (y=52, 좌측정렬) | 개인화 인사 + 상태 메시지 | **28px/44 SemiBold** · 기본 `#212529` · **강조어 = 이벤트 메인 컬러** |
| **리워드 버튼** (327×50 · radius 8) | 상태별 활성/비활성 | 활성 = **이벤트 메인 컬러** / 비활성 = **활성색 투명도 30%** · 텍스트 흰색 |
| **스탬프 그리드** | 2열 × `n/2`행 · 스탬프 `100×100` · 점선 구분선(세로1+가로) | 정밀 사양 = 아래 **2-4** |

### 2-3. 스탬프 (이벤트별 커스텀)

- 스탬프 칸 = **이벤트마다 스탬프를 커스텀 디자인해서 적용**한다. (공용 컴포넌트 인스턴스를 그대로 쓰지 않고, **이벤트 무드·브랜드에 맞춰 매번 새로 디자인** → 4유형은 §2-6)
- 단, **그리드·간격·라벨 골격은 동일하게** 유지한다(§2-4) — **칸 안 비주얼만** 이벤트별로 바뀐다. (`stamp` 컴포넌트 `6189:13747`는 이 **골격의 기준**일 뿐, 칸 디자인의 정답이 아니다.)
- **크기 = `100 × 100`** (고정).
- variant: **`active`(적립)** / **`inactive`(미적립)** 를 **한 쌍**으로 제작(이벤트 전용 컴포넌트 세트).
- **색상**: `active`(적립) = **이벤트 메인 컬러** / `inactive`(미적립) = **`#C0C0C0` 고정 회색**.
  - ⚠️ inactive는 **활성색 opacity 30%가 아니라 `#C0C0C0` 고정값**이다.

#### 스탬프 라벨(내부 텍스트) 규칙

스탬프 컴포넌트 안의 텍스트는 **해당 스탬프의 이름**이다. 이름 유무에 따라 다음과 같이 표기한다.

| 구분 | 표기 | 예 |
|---|---|---|
| **이름 없음** | **순번 숫자**(`1`, `2`, `3`, `4` …)를 그리드 순서대로 표기 | `1` · `2` · `3` · `4` |
| **이름 있음** | **스탬프 이름**을 그대로 표기 | `아메리카노` · `라떼` · `디저트` |

- 기본값은 **순번 숫자**이며, 1부터 시작해 그리드 좌→우, 위→아래 순서로 증가한다.
- 스탬프별 이름이 지정된 경우 숫자 대신 **이름**을 표기한다. (한 이벤트 안에서 이름 있는 칸·없는 칸이 섞일 수 있으며, 이름이 없는 칸은 순번 숫자 규칙을 따른다.)
- `active`/`inactive` 어느 상태든 라벨 텍스트(숫자 또는 이름)는 동일하게 유지된다.
- **라벨 색상은 칸의 상태색을 따른다** — `active` 칸 = **이벤트 메인 컬러** / `inactive` 칸 = **`#C0C0C0`**. (기본 블루 잔존 ❌)

### 2-4. 스탬프 그리드 (정밀 사양)

> 기준: 본문 폭 **327** (= 화면 375 − 좌우 여백 24). 스탬프 **`100 × 100`** · **2열 × `n/2`행**.
> 칸은 점선 구분선으로 나뉘며, 구분선은 칸과 칸 **사이 간격의 정중앙**에 위치한다.

**가로(열) 사양**

| 항목 | 값 |
|---|---|
| 열 수 | **2열** |
| 스탬프 폭 | **100** |
| 좌/우 안쪽 여백 | **31.75** (≈32) |
| 열 간격(스탬프↔스탬프) | **63.5** (≈64) |
| 세로 구분선 위치 | 두 열 사이 **정중앙** (각 스탬프에서 **31.75**) |

**세로(행) 사양**

| 항목 | 값 |
|---|---|
| 스탬프 높이 | **100** |
| 상/하 안쪽 여백 | **12** |
| 행 간격(스탬프↔스탬프) | **40** |
| 가로 구분선 위치 | 위/아래 행 **정중앙** (각 스탬프에서 **20**) |

**구분선(divider) 사양**

| 항목     | 값                                                   |
| ------ | --------------------------------------------------- |
| 종류     | **점선(dashed)**                                      |
| 두께     | **1px**                                             |
| 색상     | **`#C0C0C0`** (연한 회색)                               |
| 세로 구분선 | **행마다 1개**(= `n/2`개) · 각 행의 두 열 **정중앙** · **높이 = 행에 FILL**(행 높이에 맞춰 자동 stretch) |
| 가로 구분선 | **`(n/2) − 1`개** · **길이 = 본문 폭 327 전체** 관통 · 각 행 사이 **정중앙**(행 컨테이너 오토레이아웃 아이템) |
| 칸과의 간격 | 세로선 ↔ 스탬프 **31.75** · 가로선 ↔ 스탬프 **20** |

> 🔴 **점선 위치·길이 필수 규칙**
> - **세로선 = 행마다 세그먼트**(`n/2`개) · 각 행의 두 스탬프 **사이 간격(63.5)의 정중앙**(칸에서 31.75) · **높이는 행에 FILL** → 행을 추가/삭제하면 세로선도 자동으로 따라온다(수동 길이 조절 ❌).
> - **가로선 길이 = 327**(좌우 끝까지). 각 행 **사이 간격(40)의 정중앙**(칸에서 20) · 행 컨테이너 오토레이아웃의 아이템.
> - 점선은 **1px dashed `#C0C0C0`**.

> 🧩 **오토레이아웃 (add/remove)**: 그리드는 **행 단위**로 구성된다 — **행 = [스탬프 · 세로선(FILL) · 스탬프]**(가로 오토) , 행들은 **세로 오토레이아웃(gap 40)에 가로 구분선과 함께** 쌓인다. **"행 유닛"(스탬프 2 + 세로선 + 가로선) 단위로 복제/삭제하면 스탬프·가로선·세로선이 모두 자동 정렬**된다. (세로선이 FILL이라 별도 길이 조절 불필요)

> 📏 **스탬프 프레임(페이지) 높이 = 가변**: 헤더(top 52) + 리워드 버튼 + 스탬프 그리드를 **구성요소에 맞춰 hug**한다. **고정값이 아니며 스탬프 칸 수(n)에 따라 늘어난다.** (예: `n=6` → 약 726)
> - 단, **스탬프 그리드 ↔ 페이지 하단 간격은 n과 무관하게 항상 40 고정**이다. 칸이 늘면 **프레임 높이만 늘어나고** 하단 여백 40은 그대로 유지된다.

```
세로 리듬 (n=8 예시)          가로 리듬
┌── 상단 여백 12              ├─31.75─[스탬프 100]─31.75─┤(세로선)├─31.75─[스탬프 100]─31.75─┤
[스탬프 100]                   ↑                    ↑                    ↑
─ 20 ─ ┄┄┄ 가로선 ┄┄┄ ─ 20 ─    좌여백              세로 구분선(중앙)        우여백
[스탬프 100]
─ 20 ─ ┄┄┄ 가로선 ┄┄┄ ─ 20 ─
[스탬프 100]
─ 20 ─ ┄┄┄ 가로선 ┄┄┄ ─ 20 ─
[스탬프 100]
└── 하단 여백 12
```

> 행 수가 늘면(`n` 증가) **세로 리듬(100 → 40 → 100 → 40 …)**을 그대로 반복한다. 그리드 전체 높이 = `100 × 행수 + 40 × (행수 − 1) + 12 × 2` (행수 = `⌈n/2⌉`).
> (예: `n=8` → `100×4 + 40×3 + 24 = 542`)

> 🔢 **홀수 칸 처리 (`n`이 홀수) ⭐** — 스탬프 수가 홀수면 **마지막(맨 하단) 행은 왼쪽 칸에만 스탬프를 두고, 오른쪽 칸은 빈 여백으로** 남긴다. (스탬프를 가운데로 옮기거나 한 칸을 억지로 채우지 않는다 — **2열 그리드 정렬은 그대로**, 오른쪽 칸만 비움)
> - **행 수 = `⌈n/2⌉`** · 마지막 행 = 스탬프 **1개(좌측 칸 위치 그대로)** + **우측 칸 empty**.
> - 마지막 행의 **세로 구분선은 생략**(오른쪽에 스탬프가 없으므로) · 가로 구분선·세로 리듬(100/40)·상하 여백은 짝수일 때와 **동일**.
> - 예: `n=5` → **3행(2·2·1)**, 마지막 행은 좌측 1칸만 · `n=3` → **2행(2·1)**.

> ⚠️ **스탬프 칸 디자인은 이벤트마다 커스텀**(§2-6)이되, **그리드 골격(2열 · 100×100 · 간격 · 점선 구분선)은 동일하게** 유지한다. 칸마다 크기·간격이 들쭉날쭉한 즉석 배치 ❌ — 위 그리드 정밀 사양(간격·구분선)은 **일정한 `100×100` 칸 골격일 때만** 성립한다.

### 2-5. 헤더 텍스트 줄바꿈 (3줄 고정) ⭐

> 스탬프 헤더(개인화 + 상태 메시지)는 **항상 세 줄**로 끊는다. (어절 단위 → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-1. 시작.md]] §4-4) · 텍스트 박스 **너비 327 고정 · 높이 hug**.

```
홍길동님,
스탬프 6개를 모으고
리워드를 받으세요!
```

- **1줄** = 개인화 `"{이름}님,"`  ·  **2줄** = `"스탬프 {남은수}개를 모으고"`  ·  **3줄** = `"리워드를 받으세요!"`
  - ⭐ **{남은수} = 전체 N − 적립 수** (상태별): `3-1`(0적립)=**N** / `3-2`(1적립)=**N−1** / … `n/n`은 "모두 모았어요" 문구. → **3-2에 전체 N을 그대로 두면 오류.**
  - ⭐ **강조(메인 컬러)는 숫자에만** — 단위 **"개"·조사("를")는 강조하지 않는다**. (⚠️ 텍스트 통짜 교체 시 강조가 "N개"로 번지기 쉬움 → 숫자 범위만 재적용, CLAUDE.md)
- 인증 X(이름 없음)면 1줄을 빼고 `"스탬프 {남은수}개를 모으고"` / `"리워드를 받으세요!"` **2줄**로 구성한다.
- 완료(3-3)·수령후(3-4) 헤더처럼 문구가 달라도 **어절 단위 줄바꿈**은 동일하게 지킨다.

### 2-6. 스탬프 디자인 유형 & 적립 전·후 ⭐

> 스탬프 칸 **안에 들어가는 디자인**의 규칙. (그리드·구분선 = §2-4 · 라벨 텍스트 규칙 = §2-3)

> [!important] ⭐ 스탬프 후보 = **템플릿 복사 후 4가지만 변경** (2026-07-09 확정)
> 4유형 후보를 **매번 처음부터 그리지 않는다.** **스탬프 4유형 템플릿을 복사**한 뒤 **아래 4가지만** 바꾼다.
> - **Figma 템플릿**: `스탬프 4유형 후보 · 달·별 모티프 (시안1)` — 노드 **`6689:176`** (①텍스트만 ②이미지+텍스트 ③이미지만 ④이미지+하단리본 · 각 적립(active)/미적립(inactive) 한 쌍)
> - **변경 대상 4가지만**:
>   1. **색상** — active = 이벤트 메인 컬러 / inactive = `#C0C0C0` (고정)
>   2. **폰트 유형** — 이벤트 폰트로 (라벨·스탬프명)
>   3. **이미지** — 이벤트 모티프(로고/아이콘/thiings)로 교체 (유형 ②③④)
>   4. **텍스트 내용** — 스탬프명·날짜 등
> - 그 외 **골격(스캘럽/링·크기·간격·리본 형태·레이아웃)은 그대로 유지**한다. → 4유형 후보 제작 → 사용자 1개 선택 → 전 스탬프 통일 (보드는 페이지에 보관).
> - 아래 1)~2)의 규칙은 **템플릿에 이미 반영**돼 있으니, 모티프 판단(0)·디테일(§2-6 하단)만 확인하며 4가지를 교체한다.

**🧭 0) 디자인 요소(모티프) 판단 — 4유형 제작 *전에* 먼저** ⭐

> 스탬프를 바로 그리지 말고, **이벤트명 + 이벤트 설명 + 디자인 컨셉**을 보고 **무엇을 스탬프의 핵심 모티프로 쓸지** 먼저 판단한다. 정한 뒤 그 모티프로 **아래 4가지 유형을 모두 제작**한다(후보) → **사용자가 1개 선택** → 선택 유형으로 **전 스탬프 통일**. (4유형 후보 보드는 페이지에 보관 → [[큐알스탬프 솔루션/3. 워크플로우.md]] Step 2.5 §2-1 · [[큐알스탬프 솔루션/4. 검수 체크리스트.md]])

- **후보 모티프 (택1, 복수 가능)**:

| 모티프 | 언제 | 예 |
|---|---|---|
| **브랜드/주최 로고** | 브랜드·기관 인지가 중요한 B2B·기업·공공 이벤트 | Azure 로고 · 주최사 심볼 |
| **캐릭터/마스코트** | 캐릭터 IP·키즈·축제·팬덤 이벤트 | 행사 마스코트 (※ **얼굴(머리)만 크롭** → 아래 디테일) |
| **핵심 소재 아이콘/일러스트** | 주제를 직관적으로 보여줄 소재가 있을 때 | 카페=컵 · 전시=작품 · 콘서트=포토카드 |
| **상징 심볼/모티프(브랜드 자산)** | 공식 발자국·엠블럼 등 고유 모양이 있을 때 | 울프런 늑대 발자국 · 솥바위 기운 |
| **(모티프 없음 — 텍스트 중심)** | 쓸 만한 비주얼 자산이 없을 때 | → **유형 1(텍스트만)** |

- **판단 → 유형 연결**: 로고·캐릭터·아이콘·심볼이 **있으면 4유형 모두 후보 제작**(텍스트만 유형도 스탬프명으로 제작 가능) / **없으면(텍스트 중심)** 유형 1 위주.
- 한 이벤트 세트는 **하나의 모티프 방향으로 톤·형태를 통일**한다(칸마다 다른 모티프 ❌).

**📐 종합 조건 (가독성 — 필수)**
- 표시 크기 = 모바일에서 **약 100×100px**.
- 이미지(모티프)는 **최소 100×100px**, 스탬프명 텍스트는 **무조건 14–15px** — 이름이 잘리지 않고 또렷해야 한다. (이 범위를 벗어나는 임의 크기 ❌)
- 즉 **모티프 + 이름(14–15px)이 100×100 안에 공존**하도록 배치한다.
- 제작 단위 = 풀세트가 아니라 **하나의 스탬프 디자인에 대해 active(적립 후) / inactive(적립 전) 한 쌍** (`stamp` 컴포넌트 `6189:13747`의 베리언트처럼).

**🗂 4가지 유형**

| 유형                    | 구성                         | 핵심                                  | 레퍼런스 예                       |
| --------------------- | -------------------------- | ----------------------------------- | ---------------------------- |
| **1. 텍스트만**           | 장식 프레임 + **텍스트만** (이미지 ❌)  | **어떤 텍스트가 와도 어울리는 범용 프레임**(스캘럽/링 씰) | stamp · DREAME · 부스컵 · 물의 계곡 |
| **2. 이미지 + 텍스트 (결합)** | 아이콘 + 텍스트가 **한 배지 안에 결합**  | 둘레 곡선 텍스트 + 중앙 아이콘                  | K-01 · "스탬프 적립" 배지           |
| **3. 이미지만**           | **일러스트/로고/캐릭터 단독** (텍스트 ❌) | 이미지가 곧 스탬프                          | Azure 로고 · 캐릭터               |
| **4. 이미지 + 하단 텍스트**   | 이미지 위 + **이름 아래(리본/라벨)** · 리본 = **`리본 라벨` 컴포넌트 필수**(아래) | 이미지 메인, 이름은 아래                      | 솥바위기운 수사국 · 트레저로드 · 공모전 배지   |

**🎨 적립 전(inactive) / 후(active) 처리 규칙**

| 구성 | active (적립 후) | inactive (적립 전) |
|---|---|---|
| **이미지형 (2·3·4)** | **컬러 원본** | **채도 −100%(흑백) + 투명도 ↓** (또는 메인컬러 단색 실루엣) |
| **프레임/씰 (1)** | **메인 컬러 채움(fill)** | **`#C0C0C0` 채움(fill)** — 외곽선만 ❌, **채움으로 통일** |
| **텍스트/라벨** | 흰색 또는 메인 컬러 | 회색 (`#C0C0C0`, 채움 위 흰색 가능) |

> 적립 전/후는 **같은 디자인의 색·채도 차이**일 뿐 **레이아웃은 동일**하다.

**✨ 디테일 (퀄리티 — 필수)** ⭐
> 아래는 **선택이 아니라 필수**다. 스탬프 완성도의 **기본 요건**. **A(공통)은 4유형 모두**, **B(유형별)은 해당 유형에** — 적용 대상이면 **반드시** 적용한다.

**A. 전 유형 공통 (4유형 모두 적용)**

| 항목 | 규칙 |
|---|---|
| **형태·톤 통일** | 원형·아치·육각·티켓·밴드 등 어떤 형태든, **한 이벤트 세트는 형태·톤을 하나로 통일**한다(칸마다 제각각 ❌). |
| **캐릭터 = 얼굴(머리)만 크롭** | 캐릭터를 쓰는 **모든 유형**에서 **전신 ❌ → 얼굴(머리)만** 크롭. (100×100 작은 칸에서 얼굴이 가장 또렷·일관) |
| **모티프 = 브랜드 자산 그대로** | 발자국·심볼 등 **공식 모양이 있으면 임의로 그리지 말고 캡처/추출**해 사용. (예: 울프런 = 기획서의 늑대 발자국) |
| **⭐ 요소 그룹 = 프레임 정중앙 정렬** | 칸 안 요소(모티프·텍스트·리본 등)를 **하나의 그룹으로 묶어, 그 그룹의 bbox 중심을 원/프레임의 정중앙에 맞춘다.** 위·아래(또는 좌우)로 쏠리지 않게 **시각적 균형**을 잡는 게 핵심 — 개별 요소를 감으로 배치 ❌. (예: 이미지+하단텍스트는 [이미지+텍스트] 묶음이 원 중앙에) |
| **면(fill) 스탬프 → drop shadow 필수** | **면(채움)으로 가득 찬 스탬프**(씰·발자국·단색 실루엣 등)는 **유형과 무관하게** drop shadow로 칸과 분리·입체감. |
| └ 그림자 사양 | **`X 0 · Y 2 · Blur 1 · Spread 0` · `#000000` opacity 20%** (유형3 "이미지만" 기준으로 통일). |
| └ 저화질 보강 | 저화질 모티프(작은 마커 추출 등)는 **흰색 면적(원/사각) + 굵은 스트록(≈8px)** 위에 얹고, **텍스트가 안 읽히면 텍스트에도 그림자**. |

**B. 유형별 (해당 유형에만 적용)**

| 유형 | 필수 디테일 |
|---|---|
| **① 텍스트만** | **텍스트(스탬프명·날짜)는 스탬프(링) 정중앙에 배치** — 링 안에서 위·아래로 치우치지 않게 **가운데 정렬**(여러 줄이면 묶어서 그 블록의 중심 = 링 중심). **그런지(빈티지) 질감 필수** — worn-ink 텍스처를 **옅게 오버레이**(가독성 유지) · 밋밋한 단색 프레임 ❌. **스트록(테두리 링)은 Figma 브러시로** — 균일 기본선 하나 ❌. **구현(플러그인 API 지원됨)**: `await figma.loadBrushesAsync("STRETCH")` 후 `node.complexStrokeProperties = {type:"BRUSH", brushType:"STRETCH", brushName:"GRINDHOUSE"}`. brushName enum(대문자) = `HEIST·BLOCKBUSTER·GRINDHOUSE·BIOPIC·SPAGHETTI_WESTERN·SLASHER·HARDBOILED·VERITE·EPIC·SCREWBALL·ROM_COM·NOIR·PROPAGANDA·MELODRAMA·NEW_WAVE`(STRETCH), SCATTER는 별도 enum. **도장 느낌 추천 = `GRINDHOUSE`(외곽)·`HEIST`(내곽).** (에디터: weight 옆 stroke settings → Brush 탭) |
| **② 이미지+텍스트** | 둘레 **곡선 텍스트 + 장식(점·별)** 사이 **여백 충분히**(붙지 않게) · 텍스트 **14~15px Bold**. ⚠️ **곡률이 가파르면(반경 작아 가독성↓) 곡선 대신 직선 텍스트**. |
| **③ 이미지만** | 모티프가 곧 스탬프 — **면 스탬프 drop shadow 사양의 기준 유형**(위 A 참고) · 저화질이면 흰 면적+스트록 보강. |
| **④ 이미지+하단텍스트** | 하단 리본/라벨 = **`리본 라벨`(`6339:4`) 컴포넌트 복제·리컬러** — **형태·비율 그대로, 컬러만 메인**. variant: active `6339:2`(메인) / inactive `6339:3`(`#C0C0C0`). **라벨 텍스트만 교체**하고 리본 모양은 다시 그리지 않는다. ⭐ **리본 양 끝 날개(`Vector`)는 = 메인 컬러 + `#000000` 10%**(중앙 밴드보다 살짝 어둡게 → 접힘/입체감) · **중앙 밴드(`Rectangle`)는 메인 컬러**. [이미지 + 리본] 묶음을 **링 정중앙에 정렬**(A 공통). |

## 3. 4-상태 정의

> 강조어 = **이벤트 메인 컬러**.

| #       | 상태             | 헤더                                                  | 버튼                    | 스탬프           |
| ------- | -------------- | --------------------------------------------------- | --------------------- | ------------- |
| **3-1** | Default (수집 전) | "{이름}님, 스탬프 **{n}**개를 모으고 리워드를 받으세요!"               | "리워드 받기" · **비활성**    | 전부 `inactive` |
| **3-2** | 진행 (m개 적립)     | "{이름}님, 스탬프 **{n−m}**개를 모으고 리워드를 받으세요!" *(남은 수 강조)* | "리워드 받기" · **비활성**    | m개 `active`   |
| **3-3** | 완료·신청 (n/n)    | "{이름}님, **스탬프를 모두 모았어요!** 리워드를 신청하세요"               | "리워드 받기" · **활성**     | 전부 `active`   |
| **3-4** | 수령 후           | "{이름}님, **축하드려요!** 리워드 신청이 완료되었어요"                  | "리워드 수령 완료" · **비활성** | 전부 `active`   |

- 헤더의 숫자 = **남은 개수(n−적립수)**, 0이 되면 3-3 메시지로 전환.
- 버튼은 **n/n 적립 시에만 활성**, 수령 후 "리워드 수령 완료"(비활성).
