## ✅ 사용 원칙 (필수)

1. **한 페이지 = 1~2개 폰트.** 기본 1개(전체 통일), 디스플레이(이벤트명·"축하합니다!" 등 헤드라인)와 본문을 다르게 쓸 때만 2개. 그 이상 ❌
2. **국문 본문 = 한글 폰트 필수.** 본문·버튼·캡션 텍스트의 가독성 기준. 영문 폰트는 **장식적 영문 헤드라인·로고**에만.
3. **무드 = 색상 팔레트와 일치.** 같은 무드의 컬러 + 폰트 조합이 가장 안전.
4. **망설이면 `프리텐다드`(Pretendard).** 어느 무드에서도 실패하지 않는 본문 폴백.

## 2. 헤드라인/본문 Tier (크기 적합도)

| Tier | 사용 범위 |
|---|---|
| 🅰 **본문 전문** | 작은 크기 가독성 우수 — 본문 ⭐ + 헤드라인 가능 |
| 🅱 **전천후** | 본문·헤드라인 모두 OK (1폰트 페이지 최적) |
| 🆑 **헤드라인 전용** | 디스플레이·장식 — **본문 ❌** |

- **🅰 본문 전문(한글)**: 프리텐다드 · 본고딕 · 본명조 · KoPub돋움 · KoPub바탕 · 나눔고딕 · 나눔명조 · 부크크고딕
- **🅱 전천후(한글)**: 고운돋움 · 고운바탕 · 부크크명조 · 에스코어드림 · 조선일보명조 · 학교안심 돋보기
- **🆑 헤드라인 전용(한글)**: 태백 은하수체 · 마포꽃섬 · G마켓 산스 · 평창평화체 · HS산토끼체 · 학교안심 마법사 · 카페24 클래식타입 · 카페24 모야모야 · 베이글팻 · 와구리체 · 창원단감아삭체 · 파셜산스

## 4. 선택 의사결정

```
1. 무드 결정(9개 중 1개) — 색상 팔레트와 동일 무드
        ↓
2. 본문 한글 폰트 1개 (해당 무드의 🅰/🅱 한글)
        ↓
3. 헤드라인:
   A. 본문과 동일 폰트 통일 (가장 안전)
   B. 같은 폰트의 굵은 weight
   C. 어울리는 디스플레이 폰트 1개 추가 (위 조합표)
        ↓
4. 페이지당 1~2개 한도 확인
```

**안전 선택지**: 헤드라인+본문 모두 **프리텐다드** / 명조 페이지는 **본명조** / 럭셔리는 **본문 KoPub바탕 + 헤드라인 Playfair Display**.

## 5. 자주 하는 실수
| 실수 | 올바른 처리 |
|---|---|
| 국문 본문에 영문 폰트 적용 | 본문=한글, 영문은 헤드라인·로고만 |
| 한 페이지 폰트 3개 이상 | 최대 2개 (초과 시 텍스트→이미지) |
| 디스플레이 폰트로 본문 작성 | 디스플레이는 헤드라인 전용 |
| 무드 충돌 조합(HS산토끼체+EB Garamond 등) | 같은/인접 무드 내에서 조합 |

## 6. QR스탬프 적용 노트 — 제목용 / 본문용 분리 ⭐

> ⭐ 폰트는 **역할로 나눠 2개 사용**하는 것을 기본으로 한다 — **제목용(디스플레이)** + **본문용**. 제목까지 본문 폰트로만 두면 **힘이 없어 보여 완성도가 떨어진다**(제목은 "제목다운" 폰트로).

| 역할 | 대상 | 폰트 |
|---|---|---|
| **제목용(디스플레이)** | **이벤트명 · "축하합니다!" · "룰렛 이벤트/ROULETTE EVENT"** 등 **모든 제목류** | 무드에 맞는 **힘 있는 디스플레이/명조 폰트** (예: 감성·드리미 = **나눔명조 Bold**) |
| **본문용** | **일시·날짜·설명·안내문·핀라벨·버튼·설문** 등 모든 **본문·UI** | **Pretendard**(고정) |

- **제목류(이벤트명·축하합니다!·룰렛 이벤트)는 서로 같은 제목용 폰트로 통일**한다.
- **본문·UI는 Pretendard 고정**(가독성). 영문 폰트는 장식 영문 헤드라인·로고에만.
- 무드는 **색상 팔레트(2-2-3)와 동일**하게 잡는다.
- 페이지당 폰트 **최대 2개**(제목용 1 + 본문용 1).
