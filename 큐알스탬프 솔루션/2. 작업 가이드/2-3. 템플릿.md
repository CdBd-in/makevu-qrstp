# 🧩 2-3. 템플릿

> 이벤트마다 레이아웃을 **즉석 제작**하다 품질이 무너지는 문제(예: 여권도장 대비 **C안 루트맵 붕괴**)를 막기 위해, **검증된 레이아웃을 템플릿으로 규격화**하는 기준 문서.
> 관련: [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-3. 스탬프.md]] · [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-6. 설문지.md]] · [[큐알스탬프 솔루션/3. 워크플로우.md]] · 참조 종합 [[컨텍스트: 강현이/강현이-2026-07-07.md]]

> [!note] 이 문서의 위치
> **설계안(기준)** 문서다. 실제 Figma 템플릿 컴포넌트는 **아직 만들지 않았고**, 아래 로드맵(9절)에 따라 제작한다.

## 1. 배경 — 왜 템플릿을 늘리는가

- 현재 [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-3. 스탬프.md]]는 **2열 격자 골격 1종 + 칸(셀) 4유형**만 정의 → **3~8칸 격자만** 잘 커버.
- **격자로 안 풀리는 배치**(여정/지도·대형 10칸+·특수)는 **검증 템플릿이 없어 매번 즉석 제작** → **C안 루트맵처럼 품질 붕괴**.
- 해법: **"칸 비주얼은 커스텀, 레이아웃 골격은 템플릿"** 으로 분리하고, 빠진 레이아웃 유형을 **완성형 템플릿**으로 채운다.

## 2. 데이터 근거 (참조 이벤트 57개 집계)

### 스탬프 개수 분포 — 규모 파라미터(개수 n)의 분포

| 개수 | 3 | 4 | **5** | 6 | 7~8 | 10~14 | 17~67 | 0(미션) |
|---|---|---|---|---|---|---|---|---|
| 건수 | 6 | 10 | **16** | 7 | 4 | 6 | 3 | 2 |

- **3~6칸 = 39건(68%)** · 그중 **5칸 최다(16건)**.
- **10칸+ = 9건** — 지도·여정·스크롤형(강진·연천·청년정책넷·경기수의67 등).
- `stamp_type` **single 48/57(84%)** = 개별 칸형 압도적. 나머지(map-route·crossword·mission·image-card)는 소수 특수.
- `has_auth` **true 32 / false 24** → 인증은 on/off 모듈(기존 문서화).

## 3. 분류 원칙 — MECE ⭐

> [!important] MECE 점검으로 축 재정리 (2026-07-08)
> 이전 안은 **상호배타(ME) 위반**이 있었다 → 아래처럼 **직교 축**으로 재정리.
> - **스탬프 위반**: 개수 구간이 겹치고(같은 n이 여러 템플릿에 해당) "정형 배열"과 "경로 메타포"라는 **다른 축을 한 줄에** 나열 + n=0·특수 누락(CE 미달).
> - **설문 위반**: 라인·면처리 = **보기(낱개) 배경** 축 / 카드 = **문항(묶음) 컨테이너** 축 → **레벨 불일치**(카드+면처리 동시 성립).

**공통 원칙**: **뼈대(배열/컨테이너)는 ME·CE 유형으로 · 비주얼(셀/보기 스타일)은 직교 스왑축으로 · 규모(개수·문항수)는 축이 아니라 파라미터로.**

| 역할 | 스탬프 | 설문 |
|---|---|---|
| **뼈대 축 (ME·CE)** | 배열 유형 (§4) | 문항 컨테이너 (§5-1) |
| **비주얼 축 (직교)** | 셀 4유형 (→ 2-1-3 §2-6) | 답변 배경 (§5-2) |
| **파라미터 (축 아님)** | 개수 n → 행수·스크롤 | 문항 수·유형 |
| **조합 요소 (직교)** | — | 질문번호·필수·주관식필드·테마 (§5-3) |

→ `뼈대 유형 × 비주얼 스왑`으로 조립. 새 이벤트 = **골격 복제 + 비주얼만 교체**.

## 4. 스탬프 템플릿 기준 — 배열 유형 (MECE)

> 스탬프 배열은 **아래 4가지 중 정확히 하나**다(ME) — 넷이 모든 스탬프 페이지를 덮는다(CE).
> **개수(n)는 축이 아니라 규모 파라미터**(행수·스크롤·정렬), **칸(셀)은 4유형 직교 스왑** — 둘 다 → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-3. 스탬프.md]] §2-4 · §2-6.

> ⭐ **셀(칸) 4유형 = Figma 템플릿 확정**: `스탬프 4유형 후보` 노드 **`6689:176`**(①텍스트만 ②이미지+텍스트 ③이미지만 ④이미지+하단리본 · 각 active/inactive). 후보 제작 = **템플릿 복사 후 4가지만 변경 — ① 색상 ② 폰트 유형 ③ 이미지 ④ 텍스트 내용**(골격 유지). → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-3. 스탬프.md]] §2-6

| 유형             | 정의                  | 규모·변형(파라미터)                             | 대표 참조                           | 우선             |
| -------------- | ------------------- | --------------------------------------- | ------------------------------- | -------------- |
| **A. 정형 배열형**  | 규칙적 격자·대칭·정렬 배치 (1행·오프셋 포함) | 정렬(2열 좌측 / 중앙 대칭 / 1행 / 3+2 오프셋) × 규모(표준 hug / 대형 스크롤) | WORLD PASSPORT · 경기수의 · 송도 · 강진 · **쿠키런(1행 4열)** · **ITZY(3+2 오프셋)** | **P0**         |
| **B. 경로형**     | 여정 라인/지도 위 순번 배치    | 핀 수(4~10) · 경로 곡률                       | 청년정책넷 · 은평구 · 횡성                | **P0** (C안 빈틈) |
| **C. 특수형 (템플릿 ✗ · 커스텀 라우팅)** | A·B로 안 풀리는 **진짜 비정형**(원형 링·겹침·콜라주). **템플릿을 만들지 않고 커스텀 가이드로 처리** | — | **TCTAP(원형 프로그레스 링) — 유일 1건** | 템플릿화 안 함 (커스텀) |
| **D. 무(無)스탬프** | 스탬프 그리드 없음(미션/공유)   | —                                       | 티쏘 · 불가리 포스트카드                  | 해당 없음          |

> [!important] C(특수형)는 "유형"이 아니라 "예외 라우팅"이다 (2026-07-10)
> **템플릿화 대상은 A·B 2종**(+ D는 해당 없음)이다. C는 별도 템플릿 유형이 아니라 **"A·B로 안 풀리면 템플릿 없이 커스텀"** 을 가리키는 라우팅 표식일 뿐 — CE(포괄성) 유지를 위해 버킷으로만 남긴다.
> - **오분류 정정**: 이전 안의 `쿠키런(1행 4열)`·`ITZY(3+2 오프셋)`는 **배열이 정형(A)** 이고, 특수해 보인 건 배열이 아니라 **비주얼(IP 풀블리드 배경·전단지 무드보드)** 이었다 → A의 정렬·규모 파라미터로 흡수, 비주얼은 셀 4유형·커스텀(직교)에서 처리. → **A로 재분류.**
> - 남는 진짜 비정형 = **원형 링(TCTAP) 1건뿐** → 유일 케이스라 템플릿화 ROI 없음. 발생 시 커스텀 가이드.

> ⚠️ **B(경로형) 규격**: 다크/맵 패널 + 곡선 경로(점선) + 순번 핀 + 랜드마크 슬롯 + 진행 상태(inactive 회색 → active 메인). 핀·경로·라벨을 **규격 좌표로 고정**(C안 실패 교훈 — 즉석 배치 금지), 랜드마크는 셀 유형으로 스왑.

## 5. 설문 템플릿 기준 (MECE — 직교 2축)

> ⚠️ 설문 템플릿은 **문항 수가 아니라 디자인**으로 가른다. 단, 이전 안(라인/면처리/카드 1줄 나열)은 **레벨이 섞여** ME 위반이었다 → **직교 2축**으로 분리한다. (문항 수·유형은 파라미터)

### 5-1. 축1 · 문항 컨테이너 (ME — 문항 묶음을 어떻게 감싸나)

| | 정의 | 대표 |
|---|---|---|
| **플랫** | 문항별 컨테이너 없음 (질문+보기 나열) | 진에어 · 은평구 |
| **카드** | 문항별 화이트 카드 (radius 12 + drop-shadow) | 삼양 CRAVE LAB(퀴즈) |

### 5-2. 축2 · 답변(보기) 배경 (ME — 보기 낱개의 배경 처리)

| | 정의 | 대표 |
|---|---|---|
| **라인** | 배경 없음 · 원형 라디오 + 텍스트 | 진에어 · TGG |
| **면처리** | 채움 라운드 박스 (연한 톤 fill) | 은평구 감탄한바퀴 (`5876:2308`) |
| **아웃라인** | 테두리만 있는 박스 (fill 없음) | (카탈로그 확장 대상) |

> **축1 × 축2 는 직교** — "카드 + 면처리 보기"도 성립한다. 그래서 **이전 안의 '카드형'은 라인/면처리와 같은 레벨이 아니라** 다른 축(문항 컨테이너)이었다.

![[큐알스탬프 솔루션/attachments/survey-answer-styles.png]]
*(좌 진에어 = 플랫 × 라인 / 중 은평구 = 플랫 × 면처리 / 우 삼양 = 카드 × 라인)*

### 5-3. 축3 · 조합 요소 (직교 — 어느 조합에나 스왑)
- **질문 번호**: `Qn.` 텍스트(진에어·TGG) / **원형 뱃지 ①②③**(은평구).
- **필수 표시**: 빨간 `*`(`#FF6767`) + 헤더 안내문 (→ [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-6. 설문지.md]] §8-4).
- **주관식 필드**: 밑줄형(진에어) / 박스형(테두리).
- **테마**: 다크(라인 궁합) / 라이트(면처리·카드 궁합).

> **문항 블록 컴포넌트**(`객관식-단일`·`객관식-다중`·`주관식`)를 **축2(답변 배경)별 variant**로 두고, 문항 수·유형은 자유 조립(파라미터). 새 답변 스타일(칩/버튼·이미지 보기 등)은 축2에 값으로 추가(카탈로그 확장).

## 6. 인증 템플릿 기준 — 입력 필드 스타일 (ME) ⭐

> 인증은 **on/off 모듈**(사용 여부는 이벤트 요청 · `has_auth` true 32 / false 24). **폼 구성요소(이름·휴대폰·인증번호·동의)는 DS 고정**이므로, 템플릿은 **입력 필드 스타일** 기준 **정확히 2가지**(ME)로 가른다.

| 유형 | 입력 필드 | 특징 | 대표 |
|---|---|---|---|
| **밑줄형 (Underline)** ⭐기본 | 라벨 + **하단 밑줄** | DS 표준. 메인 컬러만 교체 | 민주평통 · 넷마블 · 세부에어 · TGG · 창대십리 · WORLD PASSPORT |
| **박스 인풋형 (Boxed)** | **외곽선/채움 라운드 박스** | 밀도 높은 폼(성별·생년월일 등)·브랜드 커스텀 | 티쏘 |

![[큐알스탬프 솔루션/attachments/auth-type-underline.png]]
*(밑줄형 — 좌 넷마블(라이트) / 우 WORLD PASSPORT(다크 반전))*
![[큐알스탬프 솔루션/attachments/auth-type-box.png]]
*(박스 인풋형 — 티쏘)*

- **직교 축(스왑)**: **명암**(라이트=다크 텍스트 / 다크=화이트 텍스트) · **메인 컬러**. 두 유형 모두에 얹는다(밝은 메인 위 텍스트는 다크 처리).
- **직교 슬롯(축 아님 · 기능 옵션)**: 이메일 추가 · 인증방법 선택(휴대폰/이메일) · 닉네임 간편 · 언어 선택. → 폼 구성 옵션일 뿐 디자인 유형과 별개.
- **파라미터**: 동의 항목 수·문구.

## 7. 룰렛 템플릿 기준 — 조각(섹터) 디자인 유형 (ME) ⭐

> 룰렛(추첨)은 **옵션 모듈**. 결과는 **당첨 리워드 N종으로 분기**(→ 2-1-5 §9).
> **공통 구조(배경 디스크 + N분할 휠 + 상단 핀)와 N분할(=리워드 수)은 고정**이고, 템플릿은 **조각을 무엇으로 구분하나** 로 나뉜다 — 스탬프 셀 4유형·설문 답변 배경(라인/면처리)과 같은 **"조각 구분" 축**. 정확히 **2가지**(ME).

| 유형                  | 조각 구분 방식                                         | 성격                   | 대표 참조                               |
| ------------------- | ------------------------------------------------ | -------------------- | ----------------------------------- |
| **A1 · 색면 교차형** ⭐기본 | 조각을 **색으로 교차 채움**(메인 투명도 단계 / 2색) + 리워드 이미지·라벨   | 대비 강함·화려 · **다크 궁합** | WORLD PASSPORT(현 §8) · 인터배터리 · 대상경주 |
| **A2 · 선 구분형**      | **얇은 구분선으로만 조각 분할**(조각 배경색 없음) · **리워드 이미지가 주인공** | 깔끔·프리미엄 · **경품 강조**  | APPLIED · 울산옹기                      |

![[큐알스탬프 솔루션/attachments/roulette-sector-styles.png]]
*(좌 A1 색면 교차 — 인터배터리 / 중·우 A2 선 구분 — APPLIED·울산옹기)*

- **화면 스펙**(확정) = [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-5. 룰렛.md]] §8 — 배경 디스크 + n등분 휠 + 핀, **n등분 규칙·조각 색상 규칙** 포함.
- **조각 내용(직교)**: 리워드 이미지 + 라벨(기본) / 라벨만 / 아이콘.
- **원판 장식(직교 · 리소스 옵션)**: 원판/조각 위에 **브랜드 일러스트·장식 보드**를 얹어 세계관·이벤트성 강화. A1·A2 **어디에나** 적용(옛 "일러스트 보드형"은 유형이 아니라 이 장식 스왑). 참조 적음 → 리소스 있을 때 **커스텀 가이드**.
- **테마(직교)**: 라이트(선 구분·밝은 원판 궁합) / 다크(색면 교차 궁합).
- **파라미터**: **N분할 = 리워드 개수**(n등분·조각 색상 규칙 → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-5. 룰렛.md]] §8-3) · 확률 표기(옵션).
- **선택**: 다크·조각 대비 강조 → **A1** / 경품 이미지 강조·깔끔 → **A2**. 룰렛 톤은 **스탬프·전체 테마와 맞춘다**(다크→A1 등).
- **A1**이 현 문서 기본형(2-1-5 §8) · **A2**가 추가 정식화 대상 · **원판 장식(일러스트)**은 직교 옵션으로 리소스 있을 때 커스텀.

## 8. 템플릿 선택 기준 (Claude가 고를 때)

> 브리프가 들어오면 아래 **판단 신호**로 스탬프·설문 템플릿을 고른다. 개수·문항 수는 템플릿을 고른 뒤 맞추는 **파라미터**다.

### 8-1. 스탬프 — 배열 유형 선택 (Q1→Q4 순서 · ME라 하나만)

| 순서 | 브리프에서 보는 신호 | 선택 |
|---|---|---|
| **Q1** | 스탬프를 **모으는 구조가 아님** (미션 완료·공유·응모형) | **D. 무스탬프** |
| **Q2** | 참여가 **여러 장소를 이동하며 도는** 여정·투어·코스 성격 (지도·동선·경로가 콘셉트의 핵심) | **B. 경로형** |
| **Q3** | 정형 정렬로 **도저히 안 되는 진짜 비정형**(원형 링·겹침·콜라주)을 요구 | **C. 특수형** → 템플릿 없이 **커스텀 가이드** |
| **Q4** | 그 외 **일반 수집형** (부스·미션 완료로 칸을 채움) | **A. 정형 배열형** ← 기본값 (1행·오프셋도 여기) |

- **A vs B 핵심 판단 = "동선/여정이 콘셉트인가"**. 예) "마을 한 바퀴 스탬프투어"·"명소 도장 여권" → **B** / "부스 5곳 QR 스캔" → **A**.
- 이후 **개수 n → 규모 파라미터**(A: 3~8 격자·10+ 스크롤·대칭 / B: 핀 4~10), **브랜드 모티프 → 셀 4유형**(2-1-3 §2-6).

### 8-2. 설문 — 두 축 각각 선택 (테마·타깃 기준)

**축1 · 문항 컨테이너**
| 신호 | 선택 |
|---|---|
| 문항 구분을 뚜렷이 · 화이트/브랜드 톤 · 문항에 이미지/길이 큼 | **카드** |
| 그 외 (대부분) | **플랫** ← 기본값 |

**축2 · 답변 배경**
| 신호 | 선택 |
|---|---|
| 다크/미니멀 테마 · 정보 밀도↑ | **라인** |
| 라이트/친근 · 시니어·가족 타깃 · 탭 타깃 크게·가독성↑ | **면처리** |
| 라이트지만 면처리가 과할 때(가볍게) | **아웃라인** |

→ 이후 **조합 요소**(질문번호·필수 `*`·주관식 필드) 선택 + 문항 수·유형 자유 조립.

### 8-3. 공통 원칙 — 스탬프와 톤 일치 + 최근접 참조

- ⭐ **설문 룩은 같은 이벤트의 스탬프 테마·셀 톤과 일치**시킨다. (다크 이벤트 → 라인 / 라이트·친근 → 면처리·카드) — 한 이벤트 안에서 스탬프·설문이 따로 놀지 않게.
- 신호가 애매하면 [[큐알스탬프 솔루션/3. 워크플로우.md]]의 **"가장 가까운 참조 이벤트 매칭"** 으로 결정(브리프와 성격이 제일 비슷한 기존 이벤트의 선택을 따름).

### 8-4. 요약 트리

```
[스탬프] 배열 유형? (템플릿화 = A·B / D 해당없음 / C 커스텀)
 ├ 스탬프 없음(미션/공유)     → D 무스탬프
 ├ 여정/투어/지도 동선       → B 경로형 (핀 4~10)
 ├ 진짜 비정형(원형 링·겹침)  → C 특수형 = 템플릿 ✗ · 커스텀 가이드 (예: TCTAP 원형 링)
 └ 그 외 일반 수집형         → A 정형배열 (정렬: 2열 / 대칭 / 1행 / 3+2 오프셋 · 규모: 3~8 격자 / 10+ 스크롤)
        → 셀 = 4유형 중 브랜드 모티프 (2-1-3 §2-6) · 특수 비주얼(IP 배경·전단지)도 여기서 커스텀

[설문] 두 축 (테마·타깃, 스탬프와 톤 일치)
 · 문항 컨테이너: 플랫(기본) / 카드(구분·브랜드)
 · 답변 배경:     라인(다크·밀도) / 면처리(라이트·친근) / 아웃라인(가볍게)
        → 조합요소 + 문항 자유 조립

[공통 옵션]
 · 인증(on/off): 밑줄형(기본) / 박스 인풋형   — 명암·컬러·폼옵션은 직교 (§6)
 · 룰렛: 조각 A1 색면교차(기본) / A2 선구분 — 원판 일러스트·테마는 직교 · 리워드 N종 분기 (§7)
 · 설문 · 리워드
```

## 9. 제작 로드맵 (우선순위)

> 모두 **Figma 컴포넌트·variant**로 **"템플릿" 전용 페이지/섹션**에 보관 → 이벤트는 복제해 사용. **현재 상태 = 전부 미제작(설계안).**

> [!important] 우선순위 = "제작 순서"이지 "중요도/필요 여부"가 아니다
> **템플릿화 대상(스탬프 A·B · 설문 조합)은 결국 다 만든다.** (C 특수형은 템플릿이 아니라 커스텀 라우팅 · D는 해당 없음.) P0/P1/P2는 **제작 순서**일 뿐, P1·P2가 불필요하다는 뜻이 아니다. 순서 기준:
> - **① 공백(gap)**: 지금 없어서 즉석 제작→붕괴하는 것부터 → **경로형(B, 여정 루트)**. (C안 실패 지점)
> - **② 빈도(coverage)**: 가장 자주 쓰는 것 → **정형 배열형 기본(A, 2열 격자 · 3~8칸 68%)**. 이미 골격이 있어 **정형화(승격)만** 하면 됨.
> - **③ ROI/대체가능성**: 임시 대체 가능하면 후순위 → A 변형(중앙 대칭·대형 스크롤) P1. **특수형(C)은 제작 대상에서 제외**(진짜 비정형 = 원형 링 1건뿐 → 템플릿 ROI 없음 · 커스텀).
>
> 즉 **경로형을 "먼저"** 라 한 건 *유일한 P0*이라서가 아니라(정형 배열 기본·설문 라인도 P0), **없는 걸 새로 만들고 C안 재발 방지가 급해서**다.

- [ ] **P0 · 스탬프 경로형(B)** — 여정 루트. 규격 좌표·경로·핀·진행상태 확정 후 컴포넌트화. (C안 빈틈)
- [ ] **P0 · 스탬프 정형 배열형 기본(A · 2열 격자)** — 2-1-3 §2-4 승격(홀수 처리 포함).
- [ ] **P0 · 설문 플랫 × 라인** + 문항 블록 3종 컴포넌트 (이미 존재 → 정형화).
- [ ] **P1 · 스탬프 A 변형(중앙 대칭 · 대형 스크롤) · 설문 플랫 × 면처리**.
- [ ] **P2 · 설문 카드 × 라인**. (스탬프 특수형(C)은 **템플릿 제작 대상 아님** — 원형 링·겹침 등 진짜 비정형은 발생 시 **커스텀 가이드**.)
- [ ] **P0 · 인증 밑줄형(기본)** — DS 폼 이미 존재 → 템플릿 정형화(명암 라이트/다크 variant).
- [ ] **P1 · 인증 박스형** · **룰렛 A1(색면 교차형)** 컴포넌트화 — 2-1-5 §8 확정 스펙(n등분·색상) 기반.
- [ ] **P2 · 룰렛 A2(선 구분형)** 정식화 · **원판 일러스트 장식(직교 옵션)** 은 리소스 있을 때 커스텀 가이드.

## 10. 원칙 요약 (MECE)
- **뼈대는 ME·CE 유형, 비주얼은 직교 스왑, 규모는 파라미터.** (§3)
- **스탬프 배열 = A/B/C/D 중 정확히 하나** (정형·경로·특수·무스탬프). **템플릿화는 A·B만** · C(특수)는 템플릿 없이 커스텀 라우팅 · D는 해당 없음. 개수·셀·1행·오프셋은 파라미터·직교 스왑.
- **설문 = 문항 컨테이너(플랫/카드) × 답변 배경(라인/면처리/아웃라인) 직교** — 카드는 라인/면처리와 다른 축.
- **여정은 경로형(B) 템플릿으로** — C안 같은 즉석 제작 재발 방지.
- 특수(C)·무스탬프(D)는 템플릿화 대신 **가이드 커스텀 / 해당 없음**.
- **인증 = 입력 필드 스타일(밑줄/박스) 2유형** (명암·컬러·폼옵션은 직교). **룰렛 = 조각 구분 방식(A1 색면교차 / A2 선구분) 2유형** (원판 일러스트·테마는 직교, N분할·리워드 수는 파라미터).
