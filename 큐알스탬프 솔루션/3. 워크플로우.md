### Step 1 — 데이터 수집 (먼저 질문하기)

> 질문 방식: **구성 옵션(B)은 구조화된 선택지 UI**(AskUserQuestion)로, **기본 정보(A)는 자유 입력**으로 받는다.

**A. 기본 정보 (페이지 콘텐츠)**
- **이벤트명** → *Figma 페이지 이름으로 사용*
- **이벤트 설명/소개 문구**
- **이벤트 일시** (행사 기간)
- **리워드(상품/혜택)가 무엇인지** — 무엇을 주는지 (예: 스타벅스 1만원 쿠폰). *리워드 카드 표기 + thiings 3D 아이콘 검색에 사용*
- **리워드 장소 / 수령 안내** (+ 수령 기한)
- 그 외(있으면): 주최·브랜드, 강조(브랜드) 컬러, 외부 링크(구글폼·네이버지도 등), 시작/리워드 배경 비주얼

**B. 구성 옵션 (구조 결정 — DS에 고정되지 않는 가변값)**
- **본인인증 필요 여부** (Y / N)
- **스탬프 개수** (몇 칸)
- **리워드 개수** (몇 개)
- **룰렛(추첨) 사용 여부** (Y / N) — Y면 **룰렛 조각(=리워드) 개수 N**도 함께 확인(원을 n등분) → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-5. 룰렛.md]]
- **설문지 사용 여부** (Y / N) — ⭐ Y면 **설문 항목(문항)·내용까지 함께 받는다**:
  - 문항별 **질문 문구**
  - 문항 **유형(객관식 / 주관식)**
  - **객관식**이면 → **보기 목록** / **주관식**이면 → **예시(placeholder) 문구**
  - (선택) 문항 **필수 응답 여부** · 설문 안내 타이틀
  - → 상세 규격 [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-6. 설문지.md]]

> ⭐ 룰렛·설문은 **본인인증과 함께 반드시 확인**할 옵션이다. 특히 **설문 Y면 문항 내용이 없으면 제작 불가** → Step 1에서 문항까지 받아야 한다.

### Step 2 — 구조 확정 (답변 수신 후)
- 플로우 결정: `시작 → (본인인증) → 스탬프(N칸) → (룰렛) → (설문) → 리워드(N개)`
  - 본인인증 N → 시작 직후 스탬프로 진입(예: 고양꽃박람회·마이크로소프트).
  - **룰렛/설문 Y → 리워드 전환 분기**(스탬프 "리워드 받기" 이후 순서)를 확정 → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-5. 룰렛.md]] §9 · [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-6. 설문지.md]] §9 (룰렛만 / 설문만 / 룰렛+설문).
- 가장 가까운 **참조 이벤트** 매칭 → [[큐알스탬프 솔루션/5. 참조 페이지/19. 솥바위기운수사국.md]] · [[큐알스탬프 솔루션/5. 참조 페이지/20. 고양꽃박람회.md]] 외 (칸 수·인증 유무 기준).
- 누락 정보가 있으면 제작 전 **재확인**.

### Step 2.5 — 리소스 분기 (있을 때 / 없을 때)

> 시작·스탬프·리워드의 **브랜드 비주얼 리소스 유무**로 갈린다. (본인인증·폼은 어느 쪽이든 항상 DS)

#### A. 리소스 있을 때 — 에셋 배치

> 네이티브 `.ai/.psd`는 **직접 읽지 못한다.** 사용자가 **export**해서 전달 → 클로드가 피그마에 배치한다.
>
> ⭐ **배경 리소스 규칙 (필수)**: 배경 이미지에는 **버튼을 포함하지 않는다.** 버튼은 **별도 레이어로 전달**받아 분리 배치한다. (스탬프도 동일 — 배경과 분리된 stamp 에셋으로)

| 원본 | export 포맷 | 클로드 처리 |
|---|---|---|
| `.ai` 벡터(로고·아이콘·라인아트) | **SVG** (폰트 outline, 효과 expand) | `use_figma`의 `createNodeFromSvg()` → 편집 가능 벡터 |
| `.ai` 복잡 일러스트 / `.psd` 배경·사진 | **PNG/JPG** (개당 ≤10MB) | `upload_assets` → 이미지 배치 |
| 전체 시안 | **PDF** | 읽어서 구조 파악 후 재구성 |

- 전달 위치: `큐알스탬프 솔루션/attachments/` 또는 경로 전달. 네이밍은 역할 기준(`start-bg.png`, `stamp-before.svg`, `reward-bg.png` 등).
- 구조적 에셋(스탬프 before/after·배경)은 **기존 이벤트 페이지에서 `download_assets → upload_assets`로 복제** 가능 → 어도비 export는 주로 **이번 이벤트 고유 비주얼**에만 필요.
- **로고**: 새로 그리지 않고 **전달받은(기존) 로고를 페이지 로고 규칙에 맞춰 크기·마스크만 수정**해 배치한다. **150×65.57 프레임에 비율유지 contain**(가로 길면 너비 150 / 세로 길면 높이 65.57)·중앙 (시작 → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-1. 시작.md]] §4-5 · 리워드 → [[큐알스탬프 솔루션/2. 작업 가이드/2-1. 페이지 구조/2-1-4. 리워드.md]] §2-3).

#### B. 리소스 없을 때 — 컬러·폰트 추론 + 이미지 생성/소싱 (DS 폴백) ⭐

> 브랜드 비주얼이 없어도 **빈 회색 박스로 두지 않는다.** 필수 입력은 **텍스트(이벤트명·설명 등)뿐**이고, **컬러·폰트는 무드에서 추론·제안**하며 **이미지(3D 아이콘·배경)는 [[큐알스탬프 솔루션/2. 작업 가이드/2-2. 디자인 요소/2-2-4. 이미지.md]] 규칙에 따라 직접 생성/소싱해 채운다.** (리워드 정보조차 없을 때만 placeholder 유지)

**1) 메인 컬러 + 폰트 톤 자동 제안** — `이벤트명+설명 → 무드 추출 → 색상 팔레트(2-2-3) + 폰트(2-2-2)를 함께 제안(근거 포함) → 사용자 확인/수정`
- 사용자가 **컬러·폰트를 명시하지 않아도** 무드를 뽑아 **컬러와 폰트를 한 세트로** 제안한다. (명시값이 있으면 그게 우선)
- **컬러** → [[큐알스탬프 솔루션/2. 작업 가이드/2-2. 디자인 요소/2-2-3. 색상팔레트.md]]에서 무드에 맞는 **팔레트 1개** 선택 → `버튼`=메인 컬러, `배경`·`텍스트`를 **한 쌍**으로 적용(흰색 고정 ❌). 메인 컬러 1개가 버튼·스탬프·배경·이미지 톤을 테마링.
- **폰트** → [[큐알스탬프 솔루션/2. 작업 가이드/2-2. 디자인 요소/2-2-2. 폰트.md]]에서 **같은 무드**의 헤드라인+본문 조합. 국문 본문 = 한글 폰트 필수, 망설이면 **프리텐다드**.
- 2-2-2·2-2-3는 **동일한 9개 무드 체계**(내추럴·페미닌·럭셔리·프로페셔널·모던·비비드·빈티지·펀·드리미)를 공유 → **한 무드에서 컬러·폰트를 함께** 가져와야 톤이 맞는다.

1. 변수·컴포넌트는 **새로 만들지 않는다** — 아래 주소록의 것을 인스턴스화해 재사용.

## 4. 클로드 작업 규약 (How Claude uses this)

**입력 → 출력 흐름**
```
[페이지 구조 가이드(2-1-1~2-1-4) + 디자인 요소·토큰 정의(2-2-1~2-2-4) + 본 주소록(3)]  →  클로드(Figma MCP)  →  [Figma 화면·컴포넌트]
```

**산출 절차**
1. 만들 단계의 **페이지 구조 가이드(2-1-1~2-1-4)** 에서 **화면·상태·콘텐츠** 확인.
2. 본 주소록에서 **기준 프레임** 복제 또는 **필요 컴포넌트** 인스턴스 배치.
3. **2-2-1의 변수·토큰**으로 색·타이포 적용 (하드코딩 금지).
4. 콘텐츠(텍스트·이미지)만 가이드대로 교체.
5. 상태(variant)·분기(본인인증 유무, 단일/다중)를 가이드대로 반영.

**MCP 참고**: `get_variable_defs`(변수) · `get_metadata`(구조/위치) · `get_design_context`(구현) · `get_screenshot`(확인) → 기존 컴포넌트 **재사용 우선**.

## 6. 이벤트 제작 시 디자인 시스템(DS) 적용 범위

> **현재 표준**: 4단계 전 화면이 **DS(2-1 페이지 구조 + 2-2 디자인 요소)를 따른다.** 이벤트별로 바뀌는 것은 **'테마'(컬러·폰트·배경/리워드 이미지·스탬프 수)뿐**이다.
> 예전 참조 이벤트(민주평통·솥바위 등 · 393폭·색 하드코딩)는 **표준화 이전 사례**일 뿐 — **신규 제작은 아래 표준(2-1·2-2)을 따른다.**

### A. 본인인증(폼) 영역 — DS를 따름
DS 컴포넌트를 **인스턴스로 그대로 재사용**한다. 경우는 둘뿐:
1. **DS 그대로** 사용, 또는
2. 이벤트 컨셉에 맞춰 **텍스트·버튼 색상만 수정** (레이아웃·컴포넌트 구조는 유지).
   - 버튼 색상 변경 시 **주 CTA + 보조 버튼("인증번호 받기" 등) 모두** 이벤트 메인 컬러로 통일한다.

| 요소 | 2-2-1 정의 | 예시 실제(393) | 차이 |
|---|---|---|---|
| 좌우 여백 | 24px | 24px | 같음 ✅ |
| Input Field | 327 폭 | 345 폭 | 폭만 ↑(여백 24 유지) |
| Button | 327 × 50 | 345 × 50 | 폭만 ↑(높이 50 동일) |
| Checkbox | 18 × 18 | 18 × 18 | 같음 ✅ |
| 컬러·타이포 토큰 | text·main·Title_L 등 | 동일 변수 | 같음 ✅ |

- **고정값은 폭이 아니라 "여백 24px"** 이다. 폭이 바뀌면 콘텐츠가 `폭 − 48`로 따라 늘어난다(375→327, 393→345). Button 높이(50)·Checkbox(18) 같은 원자 사이즈는 불변.

### B. 시작 · 스탬프 · 리워드 — DS 표준 + 이벤트 테마

이제 이 화면들도 **2-1-1~2-1-4 표준 구조**를 따른다(카드·그리드·핀 라벨·간격이 고정). 이벤트별로 바뀌는 것은 **'테마'뿐**이다:

| 요소 | DS 표준 (고정) | 이벤트별 가변 |
|---|---|---|
| 레이아웃·간격·카드·그리드·핀 라벨 | **2-1-1~2-1-4 표준** | — (변하지 않음) |
| 컬러 (메인·배경·텍스트) | 토큰(2-2-1) | **팔레트 1세트 선택**(2-2-3) |
| 폰트 | 본문 Pretendard + 디스플레이 | **무드별 폰트**(2-2-2) |
| 스탬프 | `stamp` 컴포넌트 active/inactive · 2열 점선 그리드 | **칸 수(n)** |
| 배경 | 팔레트 `배경`색 / 생성 이미지 | **무드 배경 3유형**(2-2-4) |
| 리워드·시작 이미지 | `#D9D9D9` 자리(275×172 / 275×120) | **thiings 3D 아이콘**(2-2-4) |

### 제작 시 결론
1. **본인인증 폼** = DS 컴포넌트 + 토큰 그대로(여백 24 유지 · 폭 = 아트보드 −48) — 컨셉 시 **텍스트·버튼 색상만** 수정.
2. **시작·스탬프·리워드** = **2-1 구조 + 2-2 요소 표준을 따르고**, **테마(컬러·폰트·배경·이미지·스탬프 수)만 이벤트별로** 바꾼다. *(예전처럼 "통이미지로 덮기" ❌ — 구조는 DS 표준 유지)*
3. **요청 시 확인할 가변 정보**: ① 스탬프 칸 수(n) ② 본인인증 유무 ③ 리워드(상품) ④ 메인 컬러/무드(없으면 추론) ⑤ 배경 유형 ⑥ 브랜드 에셋 유무.
