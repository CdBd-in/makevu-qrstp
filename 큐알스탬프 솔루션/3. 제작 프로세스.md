# 🧩 3. 제작 프로세스

> **큐알스탬프 이벤트 페이지를 Figma에 만드는 전 과정 가이드.** "큐알 이벤트 만들어줘" 요청을 받는 순간부터(데이터 수집 → 구조 확정 → 리소스 준비 → 페이지 제작)를 **1절**에 담았다.
> 토큰·컴포넌트의 *값·용도 정의*는 [[큐알스탬프 솔루션/2. 디자인 가이드/2-1. 공통 디자인 시스템.md]], 실제 이벤트 예시는 [[큐알스탬프 솔루션/4. 참조 페이지/1. 민주평통.md]]에 있다.
> 이 문서가 직접 관리하는 것 → ① **제작 워크플로우**(1절) ② **Figma 주소록(node-id)**(3절) ③ **작업 규약 · DS 적용 범위**(4·6절).
> ※ 컬러·타이포·컴포넌트 스펙은 2-1을 단일 출처로 본다. (여기서 중복 표기하지 않음)

## 1. 이벤트 페이지 제작 프로세스

> 사용자가 **"큐알 이벤트를 만들어줘"** 라고 하면, 곧바로 제작하지 말고 아래 **Step 1(데이터 수집)** 을 먼저 질문한다.
> 대상 Figma 파일: `QR 스탬프` · fileKey `n8YIkPdm2svezJYjePHn1u`
> ([Flow 진입점 81:1117](https://www.figma.com/design/n8YIkPdm2svezJYjePHn1u/QR-스탬프?node-id=81-1117))

### Step 1 — 데이터 수집 (먼저 질문하기)

> 질문 방식: **구성 옵션(B)은 구조화된 선택지 UI**(AskUserQuestion)로, **기본 정보(A)는 자유 입력**으로 받는다.

**A. 기본 정보 (페이지 콘텐츠)**
- **이벤트명** → *Figma 페이지 이름으로 사용*
- **이벤트 설명/소개 문구**
- **이벤트 일시** (행사 기간)
- **리워드 장소 / 수령 안내**
- 그 외(있으면): 주최·브랜드, 리워드 수령 기한, 강조(브랜드) 컬러, 외부 링크(구글폼·네이버지도 등), 시작/리워드 배경 비주얼

**B. 구성 옵션 (구조 결정 — DS에 고정되지 않는 가변값)**
- **본인인증 필요 여부** (Y / N)
- **스탬프 개수** (몇 칸)
- **리워드 개수** (몇 개)

### Step 2 — 구조 확정 (답변 수신 후)
- 플로우 결정: `시작 → (본인인증) → 스탬프(N칸) → 리워드(N개)`
  - 본인인증 N → 시작 직후 스탬프로 진입(예: 고양꽃박람회·마이크로소프트).
- 가장 가까운 **참조 이벤트** 매칭 → [[큐알스탬프 솔루션/4. 참조 페이지/1. 민주평통.md]] 외 (칸 수·인증 유무 기준).
- 누락 정보가 있으면 제작 전 **재확인**.

### Step 2.5 — 리소스 준비 (어도비 → 피그마)

> 네이티브 `.ai/.psd`는 **직접 읽지 못한다.** 사용자가 **export**해서 전달 → 클로드가 피그마에 배치한다.
>
> ⭐ **배경 리소스 규칙 (필수)**: 배경 이미지에는 **버튼을 포함하지 않는다.** 버튼은 **별도 레이어로 전달**받아 분리 배치한다. (스탬프도 동일 — 배경과 분리된 stamp 에셋으로)

| 원본 | export 포맷 | 클로드 처리 |
|---|---|---|
| `.ai` 벡터(로고·아이콘·라인아트) | **SVG** (폰트 outline, 효과 expand) | `use_figma`의 `createNodeFromSvg()` → 편집 가능 벡터 |
| `.ai` 복잡 일러스트 / `.psd` 배경·사진 | **PNG/JPG** (개당 ≤10MB) | `upload_assets` → 이미지 배치 |
| 전체 시안 | **PDF** | 읽어서 구조 파악 후 재구성 |

- 전달 위치: `큐알스탬프 솔루션/attachments/` 또는 경로 전달. 네이밍은 역할 기준(`start-bg.png`, `stamp-before.svg`, `reward-bg.png` 등).
- 구조적 에셋(스탬프 before/after·배경)은 **기존 이벤트 페이지에서 `download_assets → upload_assets`로 복제** 가능 → 어도비 export는 주로 **이번 이벤트 고유 비주얼**에만 필요.

### Step 3 — Figma 페이지 생성 & 제작
1. 파일에 **새 페이지 추가**, 페이지명 = **이벤트명**.
2. **디자인 가이드 준수**(2. 디자인 가이드 / DS): **375 폭 · 24 여백 · 콘텐츠 326** (기본). 이벤트가 더 넓은 아트보드(예: 393)를 쓰면 **여백 24는 유지**한 채 콘텐츠 폭만 조정 → 6절.
   - 본인인증·버튼·체크박스·텍스트는 **DS 컴포넌트/토큰 그대로 재사용**(폼 폭 = 아트보드 − 48).
   - 색·타이포는 **변수명으로 적용**(하드코딩 금지) — 2절·6절 원칙.
3. **단계별 상태 프레임** 생성: 본인인증(Default/Filled) · 스탬프(Default/진행/완료/RewardDone) · 리워드(Default/(정보입력)/Done).
   - ⭐ **필수**: 스탬프는 **before(수집 전) + after(수집 완료) 상태 페이지를 둘 다** 제작한다. (스탬프 리소스는 before/after 두 벌로 전달받아 분리 배치)
4. **가변 비주얼 반영**: 스탬프 칸 수·형태, 시작·리워드 배경 이미지, 강조 컬러를 입력받은 이벤트 값으로 교체(→ 6절 B 참고).
5. 완료 후 스크린샷으로 확인하고, 필요 시 참조 페이지 폴더에 새 예시로 기록.

> ✅ 요약: **질문(Step1) → 구조 확정(Step2) → 페이지 생성·DS 적용·가변 반영(Step3)** 순으로 진행한다.

## 2. 원칙

1. 변수·컴포넌트는 **새로 만들지 않는다** — 아래 주소록의 것을 인스턴스화해 재사용.

## 4. 클로드 작업 규약 (How Claude uses this)

**입력 → 출력 흐름**
```
[단계 가이드(2-2~2-5) + 토큰·컴포넌트 정의(2-1) + 본 주소록(3)]  →  클로드(Figma MCP)  →  [Figma 화면·컴포넌트]
```

**산출 절차**
1. 만들 단계의 가이드(2-2~2-5)에서 **화면·상태·콘텐츠** 확인.
2. 본 주소록에서 **기준 프레임** 복제 또는 **필요 컴포넌트** 인스턴스 배치.
3. **2-1의 변수**로 색·타이포 적용 (하드코딩 금지).
4. 콘텐츠(텍스트·이미지)만 가이드대로 교체.
5. 상태(variant)·분기(본인인증 유무, 단일/다중)를 가이드대로 반영.

**MCP 참고**: `get_variable_defs`(변수) · `get_metadata`(구조/위치) · `get_design_context`(구현) · `get_screenshot`(확인) → 기존 컴포넌트 **재사용 우선**.

## 6. 이벤트 제작 시 디자인 시스템(DS) 적용 범위

> 참조 이벤트(민주평통·솥바위·고양꽃박람회·마이크로소프트, → [[큐알스탬프 솔루션/4. 참조 페이지/1. 민주평통.md]])를 분석한 결과.
> 모든 예시는 **393 폭**이며, 내부 요소는 **"DS 그대로 쓰는 영역"과 "이벤트별 커스텀 영역"으로 명확히 갈린다.**
> 근거: 본인인증 폼 노드(`5864:1658`)는 DS 변수(`black`·`selected #4B73FF`·`Title_L`·`Field txt_L`·`Input Text`·`link_ul`)를 그대로 사용 / 스탬프 노드(`5174:104`)는 변수 `{}`(미사용, 색 하드코딩된 이미지·벡터).

### A. 본인인증(폼) 영역 — DS를 따름
DS 컴포넌트를 **인스턴스로 그대로 재사용**한다. 경우는 둘뿐:
1. **DS 그대로** 사용, 또는
2. 이벤트 컨셉에 맞춰 **텍스트·버튼 색상만 수정** (레이아웃·컴포넌트 구조는 유지).
   - 버튼 색상 변경 시 **주 CTA + 보조 버튼("인증번호 받기" 등) 모두** 이벤트 메인 컬러로 통일한다.

| 요소 | 2-1 정의 | 예시 실제(393) | 차이 |
|---|---|---|---|
| 좌우 여백 | 24px | 24px | 같음 ✅ |
| Input Field | 326 폭 | 345 폭 | 폭만 ↑(여백 24 유지) |
| Button | 326 × 50 | 345 × 50 | 폭만 ↑(높이 50 동일) |
| Checkbox | 18 × 18 | 18 × 18 | 같음 ✅ |
| 컬러·타이포 토큰 | black·selected·Title_L 등 | 동일 변수 | 같음 ✅ |

- **고정값은 폭이 아니라 "여백 24px"** 이다. 폭이 바뀌면 콘텐츠가 `폭 − 48`로 따라 늘어난다(375→327, 393→345). Button 높이(50)·Checkbox(18) 같은 원자 사이즈는 불변.

### B. 시작 · 스탬프 · 리워드 영역 — DS와 다름(이벤트별 커스텀)

| 항목 | 2-1 정의 | 예시 실제 |
|---|---|---|
| 스탬프 크기/형태 | 100×100, 2열 점선 그리드 | 이벤트마다 다름: 민주평통 110×110 원형 / 솥바위 141×137 지그재그 / 고양 140×150 작품카드 / MS 132×132 |
| **스탬프 칸 수** | (정하지 않음) | 16 / 3 / 6 / 4 — **요청 시 함께 전달받아야 하는 값** |
| 변수 사용 | 토큰 기반 | 변수 없음(`{}`) = 색 하드코딩된 비트맵/벡터 아트 |
| 시작·리워드 화면 | 375 골격 | DS 컴포넌트 아님 → 풀블리드 배경 이미지 + 버튼 오버레이 |
| 화면 높이 | 812 고정 | 705 / 819 / 946 / 1502 / 1679 / 1809 (롱폼까지) 가변 |
| 강조 컬러 | `#4B73FF` 단일 | 이벤트 브랜드색으로 교체(솥바위 레드 · 민주평통 네이비 · 고양 퍼플 · MS 블루) |

- 이 영역은 **이벤트 브랜드 비주얼을 따라가 기본 UI를 거의 쓰지 않는다.** 따라서 제작 시:
  - **리소스 에셋(시작·스탬프·리워드 비주얼)을 받아 그 에셋에 맞춰 디자인**하고,
  - 그 안에 들어가는 **내용(문구·텍스트 위계 등)만 DS를 참고**해 제작한다.

### 제작 시 결론
1. **본인인증 폼**은 DS 컴포넌트(필드/체크박스/버튼) + 토큰을 **그대로** 인스턴스화한다(여백 24 유지 · 폭은 아트보드 −48: 375→326 / 393→345) — 컨셉에 맞출 땐 **텍스트·버튼 색상만** 수정.
2. **시작·스탬프·리워드**는 **받은 리소스 에셋에 맞춰 디자인**하고 **내부 콘텐츠(문구)만 DS 참고** — 기본 UI는 거의 쓰지 않으며, DS 스탬프 그리드는 기본 예시일 뿐 대개 오버라이드된다.
3. **요청 시 반드시 확인할 가변 정보**: ① 스탬프 칸 수 ② 본인인증 유무 ③ 스탬프 형태/배치 ④ 시작·리워드 배경 비주얼 ⑤ 강조 컬러 ⑥ 화면 높이(일반/롱폼).
